## 🎯 根因分析 · g1

### 因果链

```text
应用内部服务依赖不可用 → /work 等端点返回 503 状态码 → Readiness Probe 探测失败 (获取 503 或连接拒绝) → Pod 状态变更为 NotReady
```

### 根因结论

已确认的根因是：**应用内部服务依赖不可用导致 Readiness Probe 探测失败。**

* **机制说明**：应用进程正常运行 (Restart=0, Running)，但其内部依赖的服务/资源不可用，导致 HTTP 请求返回 503 状态码。
* **影响传导**：Kubernetes 配置的 Readiness Probe 探测端点（如 `/ready` 或 `/work`）因持续返回 503 或偶尔 Connection Refused，被标记为不健康，从而将 Pod 状态置为 `NotReady`。
* **证据引用**：该结论由 K8s Event (2, 3) 直接记录探针失败状态，并由 Logging (5) 和 Tracing (6) 提供了“依赖不可用”及“503 响应”的确切事实支撑。

* **未确认项**：具体是哪个下游服务或资源导致了“dependency unavailable”尚不明确，现有日志仅记录了业务侧的报错模式，缺乏底层资源（如数据库、其他微服务）的连通性追踪或资源指标证据。
