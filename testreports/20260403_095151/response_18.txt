## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 调整EmptyDir卷的sizeLimit**
如果应用确实需要更多临时存储空间，可以修改Deployment中`logs`卷的`sizeLimit`。
```bash

# 编辑yaml文件，找到名为logs的emptyDir卷，将sizeLimit调整为更大的值，例如100Mi
# 然后应用更新
kubectl apply -f logfill-deployment.yaml
```
*依据*：当前30Mi限制被突破，需根据应用实际需求调整。

**2. [关键] 检查并优化logfill应用行为**
检查应用代码或配置，确认其为何持续向`/logs`目录写入数据。如果是日志，应配置日志轮转或调整日志级别；如果是临时数据，应增加清理逻辑。
```bash
# 查看当前正在运行的logfill Pod的日志，分析写入内容
kubectl logs -f logfill-7dc47758f6-cf5xj -n aiops-e2e
```
*目的*：从源头减少数据写入量或实现自动清理。

**3. [可选] 清理被驱逐的Pod**
被驱逐的Pod（状态为`ContainerStatusUnknown`）通常不会自动删除，可以手动清理。
```bash
kubectl delete pod logfill-7dc47758f6-8kfr6 logfill-7dc47758f6-dkxnl -n aiops-e2e
```
