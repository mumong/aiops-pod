## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为 Pod 添加对应的容忍度 (Toleration)**
如果 Pod 必须运行在 `node2` 上（例如，该节点有特殊硬件），则修改其部署，添加容忍该污点的配置。
```bash
# 假设通过 Deployment 管理，编辑 Deployment
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
在 Pod 模板规范 (`spec.template.spec`) 中添加：
```yaml
tolerations:
- key: "test-unschedulable"
  operator: "Equal"
  value: "true"
  effect: "NoSchedule"
```

**2. [推荐] 移除节点 `node2` 上的污点**
如果 `node2` 不应被标记为不可调度，则移除该污点。
```bash
kubectl taint nodes node2 test-unschedulable=true:NoSchedule-
```

**3. [可选] 修改 Pod 的 nodeSelector**
如果 Pod 不一定非要运行在 `node2` 上，可以修改其 `nodeSelector`，使其可以调度到其他节点（如 `node1`）。
```bash
# 编辑 Deployment，将 nodeSelector 修改为其他可用节点，或直接删除
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
将 `nodeSelector` 修改为：
```yaml
nodeSelector:
  kubernetes.io/hostname: node1
# 或直接删除整个 nodeSelector 字段
```
