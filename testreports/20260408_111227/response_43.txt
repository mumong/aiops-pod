## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为 Pod 添加对应的污点容忍度 (Toleration)**
如果业务允许 Pod 在 `node2` 上运行，修改其 Deployment 或 Pod 模板，添加容忍度。
```bash
# 编辑 Deployment
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
在 `spec.template.spec` 部分添加：
```yaml
tolerations:
- key: "test-unschedulable"
  operator: "Equal"
  value: "true"
  effect: "NoSchedule"
```
*依据*：使 Pod 能够容忍 `node2` 的污点，从而被调度。

**2. [替代方案] 移除 node2 上的污点**
如果 `node2` 不应被设置为不可调度，则移除该污点。
```bash
kubectl taint nodes node2 test-unschedulable=true:NoSchedule-
```
*依据*：清除调度障碍，使所有 Pod（无需特殊容忍）都能调度到 `node2`。

**3. [替代方案] 修改 Pod 的 nodeSelector**
如果 Pod 不一定非要运行在 `node2` 上，修改其调度约束。
```bash
# 编辑 Deployment，将 nodeSelector 改为其他节点（如 node1）或删除
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
*依据*：让 Pod 避开有污点的 `node2`，调度到其他可用节点。

### 后续优化
1.  **污点管理规范**：建立节点污点的使用和审批流程，避免生产环境出现意外的 `NoSchedule` 污点。
2.  **Pod 调度策略检查**：在 CI/CD 流程中，对 Pod 的 `nodeSelector`、`affinity` 与集群节点的 `Taint`、`Label` 进行兼容性检查。
