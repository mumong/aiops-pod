## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查并处理节点污点**
```bash
# 查看 node2 的污点信息
kubectl describe node node2 | grep -A 5 Taints
```
*依据*：这是导致“标签匹配但无法调度”的最常见原因。
- **如果存在污点**（如 `node.kubernetes.io/unschedulable:NoSchedule`），根据情况选择：
    - **为 Pod 添加容忍度**（修改 Deployment）：
        ```yaml
        tolerations:
        - key: "node.kubernetes.io/unschedulable"
          operator: "Exists"
          effect: "NoSchedule"
        ```
    - **移除节点污点**（如果节点已恢复正常）：
        ```bash
        kubectl taint nodes node2 node.kubernetes.io/unschedulable:NoSchedule-
        ```

**2. [其次] 检查节点资源情况**
```bash
# 查看 node2 的可用资源总量和已分配量
kubectl describe node node2 | grep -A 10 -B 5 "Allocatable:\|Allocated resources:"
```
*依据*：资源不足是 Pending 的另一大原因。
- **如果资源不足**，考虑：
    - 清理 `node2` 上不必要的 Pod。
    - 调整该 Pod 的资源请求（`requests`）到更小值。
    - 将 Pod 调度到其他有资源的节点（修改或删除 `nodeSelector`）。

**3. [可选] 查看更详细的 Pod 事件**
```bash
kubectl describe pod l1-test-nginx-6c69dc7c76-sxwsp -n aiops-e2e
```
*目的*：获取比 `kubectl events` 更详细的事件历史，可能包含更具体的失败原因。

### 后续优化
1.  **为关键节点添加污点管理策略**，避免误操作导致调度失败。
2.  **配置资源监控与告警**，在节点资源水位过高时提前预警。
3.  **使用 Pod 拓扑分布约束或亲和性**替代严格的 `nodeSelector`，提高调度灵活性。
