## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为 Pod 添加容忍度（Toleration）**
如果业务允许 Pod 在 `node2` 上运行，修改其控制器（如 Deployment），添加对污点 `test-unschedulable` 的容忍。
```bash

```
*依据*：使 Pod 能够容忍 `node2` 的污点，从而满足调度条件。

**2. [替代方案] 修改 Pod 的节点选择器**
如果 Pod 不一定非要运行在 `node2` 上，可以修改节点选择器，使其可以调度到 `node1` 或 `master`。
```bash

# 或指定调度到 node1
kubectl patch deployment l1-test-nginx -n aiops-e2e --type='json' -p='[{"op": "replace", "path": "/spec/template/spec/nodeSelector", "value": {"kubernetes.io/hostname": "node1"}}]'
```
*依据*：避开有冲突污点的节点。

**3. [根本解决] 移除 node2 的污点**
如果 `test-unschedulable` 污点是测试或临时设置，且不再需要，可以直接移除它。
```bash
kubectl taint nodes node2 test-unschedulable:NoSchedule-
```
*依据*：从节点层面解除调度限制，这是最彻底的解决方式。**执行前请确认该操作符合集群管理意图。**
