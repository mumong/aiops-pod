## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为Pod添加对应的污点容忍度**
如果该Pod需要调度到 `node2`，修改其部署（Deployment）的Pod模板，添加容忍度。
```bash
# 首先获取当前Deployment的名称
kubectl get deployment -n aiops-e2e -l app=nginx

# 假设Deployment名为 l1-test-nginx，为其添加容忍度
kubectl patch deployment l1-test-nginx -n aiops-e2e --type='json' -p='[{"op": "add", "path": "/spec/template/spec/tolerations", "value": [{"key": "test-unschedulable", "operator": "Equal", "value": "true", "effect": "NoSchedule"}]}]'
```
*依据*：使Pod能够容忍 `node2` 的污点，从而被调度。

**2. [替代方案] 移除 node2 上的污点**
如果 `node2` 不应该被标记为不可调度，则移除该污点。
```bash
kubectl taint nodes node2 test-unschedulable=true:NoSchedule-
```
*依据*：从根本上解除调度限制。**请谨慎操作，确保移除污点符合集群管理意图。**

**3. [检查] 确认Pod是否绑定了node2**
检查Pod或Deployment的配置，看是否使用了 `nodeSelector` 强制指定了 `node2`。
```bash
kubectl get deployment l1-test-nginx -n aiops-e2e -o yaml | grep -A5 -B5 nodeSelector
```
*目的*：如果存在绑定，且 `node2` 因其他原因（如资源不足）不可用，需考虑修改节点选择器或调整资源。

### 后续优化
1.  **污点与容忍度管理**：建立清晰的污点使用规范，确保应用部署时配置正确的容忍度。
2.  **资源规划与监控**：监控节点资源使用情况，避免因资源不足导致类似调度失败。
3.  **预检机制**：在部署前，使用 `kubectl describe node` 检查目标节点的污点和资源状态。
