## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为 Pod 添加对应的污点容忍 (Toleration)**
如果该 Pod 确实需要运行在 `node2` 上，修改其 Deployment 或 Pod 模板，添加容忍。
```bash

```
*依据*：使 Pod 能够容忍 `node2` 的污点，从而被调度。

**2. [替代方案] 移除 Pod 的 nodeSelector 约束**
如果 Pod 不一定非要运行在 `node2` 上，移除 `nodeSelector` 约束，使其可以调度到其他无污点的节点（如 `node1`）。
```bash

```
*依据*：解除对 `node2` 的强制绑定，让调度器选择其他可用节点。

**3. [管理操作] 移除 node2 的污点**
如果 `node2` 上的 `test-unschedulable` 污点是临时设置且不再需要，可以将其移除。
```bash

```
*依据*：从根本上解除节点的调度限制。**（执行前请确认该操作符合集群管理意图）**
