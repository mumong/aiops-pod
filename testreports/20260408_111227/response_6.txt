## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为 Pod 添加对应的容忍（Toleration）**
如果 Pod 必须运行在 `node2` 上，修改其 Deployment 或 Pod 模板，添加容忍该污点。
```bash
# 假设通过 Deployment 管理，编辑 Deployment
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
在 `spec.template.spec` 下添加：
```yaml
tolerations:
- key: "test-unschedulable"
  operator: "Equal"
  value: "true"
  effect: "NoSchedule"
```
*依据*：使 Pod 能够容忍 node2 的污点，从而被调度。

**2. [替代方案] 移除 node2 节点的污点**
如果该污点是测试或误操作添加的，可以将其移除。
```bash
kubectl taint nodes node2 test-unschedulable=true:NoSchedule-
```
*依据*：直接消除调度障碍。

**3. [替代方案] 修改 Pod 的节点选择器**
如果 Pod 不一定非要运行在 `node2` 上，可以修改其 `nodeSelector`，使其能调度到其他节点（如 `node1`）。
```bash
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
将 `nodeSelector` 修改为：
```yaml
nodeSelector:
  kubernetes.io/hostname: node1
```
*依据*：将 Pod 调度到没有污点的节点。
