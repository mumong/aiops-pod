## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查并修复 Pod 的调度配置**
首先，查看该 Pod 或其所属 Deployment 的配置：
```bash
kubectl get deployment l1-test-nginx -n aiops-e2e -o yaml
```
或直接查看 Pod 模板：
```bash
kubectl get pod l1-test-nginx-6c69dc7c76-sxwsp -n aiops-e2e -o yaml | grep -A 10 -B 5 tolerations
```
**修复方案A（推荐）：为 Pod 添加容忍度，允许调度到 master 节点。**
编辑 Deployment：
```bash
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
在 `spec.template.spec` 下添加：
```yaml
tolerations:
- key: node-role.kubernetes.io/control-plane
  operator: Exists
  effect: NoSchedule
```
**修复方案B：确保 Pod 能调度到 node1 或 node2。**
检查节点资源并可能添加 `nodeSelector`：
```bash
kubectl describe node node1 | grep -A 5 -i allocatable
kubectl describe node node2 | grep -A 5 -i allocatable
```
在 Deployment 的 `spec.template.spec` 下添加节点选择器（例如调度到 node1）：
```yaml
nodeSelector:
  kubernetes.io/hostname: node1
```

**2. [可选] 临时移除 master 节点的污点（不推荐用于生产控制平面）**
```bash
kubectl taint nodes master node-role.kubernetes.io/control-plane:NoSchedule-
```
*注意：这会使普通 Pod 可能调度到控制平面节点，存在安全与稳定性风险。*

### 后续优化
1.  **资源监控**：为 node1 和 node2 配置资源使用率监控和告警（CPU >80%， 内存 >80%），避免因资源不足导致新的调度失败。
2.  **调度策略**：考虑使用 `PodAntiAffinity` 分散应用负载，或配置 `ResourceQuota` 管理命名空间资源。
3.  **污点与容忍度管理**：明确集群的污点策略，并为需要调度到特定节点的工作负载统一配置容忍度。
