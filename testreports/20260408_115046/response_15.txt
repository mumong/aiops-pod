## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查节点网络连通性**
在故障 Pod 所在节点 (`node2`) 上执行，诊断网络问题：
```bash
# 登录到 node2 节点，执行以下命令
# 测试 DNS 解析
nslookup registry-1.docker.io
# 测试到仓库端口的 TCP 连通性 (HTTPS 端口 443)
telnet registry-1.docker.io 443
# 或使用 curl 测试 HTTPS 请求 (可能更接近实际拉取行为)
curl -v https://registry-1.docker.io/v2/ --connect-timeout 10
```
*目的*：确认问题是出在节点网络出口，还是全局性网络故障。
**2. [可选] 临时使用本地或可访问的镜像**
如果应用紧急，可以修改 Pod 或 Deployment 的镜像地址，指向一个内部可访问的镜像仓库或已缓存的镜像。
```bash
# 例如，如果有一个内部仓库 mirror.registry.com
kubectl set image deployment/<your-deployment> <container-name>=mirror.registry.com/nginx:latest -n <namespace>
```
*注意*：这只是一个临时规避方案。
**3. [排查] 检查网络策略和防火墙**
检查是否有 NetworkPolicy 或节点防火墙规则阻止了出站流量。
```bash
# 查看所有 NetworkPolicy
kubectl get networkpolicy -A
# 查看 calico 网络策略 (如果使用 Calico CNI)
kubectl get globalnetworkpolicy -A
```
### 后续优化
1.  **配置镜像仓库镜像或加速器**：在 Docker Daemon 或 Containerd 配置中，为 `registry-1.docker.io` 配置国内镜像加速器（如中科大、阿里云镜像源），避免依赖不稳定的国际链路。
2.  **使用私有镜像仓库**：将常用镜像推送至内网私有仓库（如 Harbor），从根本上避免对外部网络的依赖。
3.  **配置 Pod 的 imagePullPolicy**：对于稳定版本的应用镜像，可以考虑使用 `imagePullPolicy: IfNotPresent`，优先使用节点本地已存在的镜像。
