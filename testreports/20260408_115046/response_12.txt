## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查异常Pod的详细事件，获取具体错误信息**
```bash
# 检查第一个异常Pod的事件
kubectl describe pod imagepull-fail-victim -n aiops-e2e | grep -A 10 -B 5 "Events:"
# 或直接查看事件
kubectl get events -n aiops-e2e --field-selector involvedObject.name=imagepull-fail-victim

# 检查第二个异常Pod的事件
kubectl describe pod disk-check -n default | grep -A 10 -B 5 "Events:"
```
*目的*：获取如 `Failed to pull image "xxx": rpc error: code = Unknown desc = ...` 的具体错误，这是诊断的关键。

**2. [关键] 验证Pod配置的镜像名称和拉取密钥**
```bash
# 查看Pod定义的镜像名称
kubectl get pod imagepull-fail-victim -n aiops-e2e -o jsonpath='{.spec.containers[0].image}'
kubectl get pod disk-check -n default -o jsonpath='{.spec.containers[0].image}'

# 检查Pod是否配置了imagePullSecrets
kubectl get pod imagepull-fail-victim -n aiops-e2e -o jsonpath='{.spec.imagePullSecrets[*].name}'
```
*依据*：确认镜像地址是否正确，以及是否配置了访问私有仓库所需的Secret。

**3. [执行] 根据错误信息采取对应措施**
- **如果错误是 `404 Not Found`**：修正镜像名称或标签。
- **如果错误是 `401 Unauthorized`**：创建或更新 `imagePullSecret`。
    ```bash
    # 示例：创建docker-registry类型的Secret
    kubectl create secret docker-registry <secret-name> \
      --docker-server=<your-registry-server> \
      --docker-username=<your-username> \
      --docker-password=<your-password> \
      --docker-email=<your-email> \
      -n <namespace>
    # 更新Pod或其Deployment/DaemonSet以引用此Secret
    ```
- **如果错误是网络超时**：检查节点防火墙、网络策略，或尝试从节点手动拉取镜像进行测试。

### 后续优化
1.  **镜像仓库可用性监控**：对关键镜像仓库配置网络探针或健康检查。
2.  **使用明确的镜像标签**：避免使用 `latest` 标签，使用具体的版本号或摘要(SHA256)。
3.  **预拉取镜像**：对于关键镜像，可在节点初始化脚本中提前拉取。
