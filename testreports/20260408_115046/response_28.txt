## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 诊断节点网络连通性**
在受影响的节点（如 `node2`）上执行网络测试，确认问题范围。
```bash
# 登录到 node2 节点（假设通过 SSH）
ssh node2

# 测试到 Docker Hub 的 HTTPS 端口连通性
curl -v https://registry-1.docker.io/v2/ 2>&1 | head -20
# 或使用 telnet 测试 TCP 443 端口
telnet registry-1.docker.io 443
```
*目的*：获取直接网络层证据，确认是集群出口问题还是外网服务问题。

**2. [可选] 检查并调整网络策略或防火墙**
如果上一步确认是集群出口问题，检查可能阻止出口流量的配置。
```bash
# 检查是否存在限制出口的 NetworkPolicy
kubectl get networkpolicy -A
# 检查节点防火墙规则 (需在节点执行)
sudo iptables -L -n | grep -i docker
sudo iptables -L -n | grep -i 443
```

**3. [临时] 使用本地或可访问的镜像仓库**
如果业务紧急，可将所需镜像推送到集群内可访问的私有仓库，并修改Pod的镜像地址。
```bash
# 修改 Deployment 或 Pod 的镜像地址
kubectl set image deployment/<your-deployment> -n <namespace> <container-name>=<your-private-repo>/nginx:latest
```

### 后续优化
1.  **配置镜像仓库代理或加速器**：在 `kubelet` 或容器运行时配置国内镜像加速器（如阿里云、腾讯云镜像加速地址），减少对 Docker Hub 的直接依赖。
2.  **部署私有镜像仓库**：搭建 Harbor 等私有仓库，将常用镜像缓存到内网，避免受外网波动影响。
3.  **监控外部服务可达性**：通过集群内的网络诊断 Pod 或外部监控，对关键外部服务（如公共镜像仓库）进行定期连通性探测和告警。
