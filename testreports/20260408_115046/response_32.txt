## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查 node2 节点到公网的基础连通性**
登录到 `node2` 节点执行以下命令：
```bash
# 1. 检查DNS解析
dig registry-1.docker.io
nslookup registry-1.docker.io

# 2. 检查基础网络连通性 (ICMP可能被禁，仅供参考)
ping -c 4 8.8.8.8

# 3. 检查到Docker仓库的TCP端口连通性 (HTTPS 443)
timeout 5 curl -v https://registry-1.docker.io/v2/ || telnet registry-1.docker.io 443

# 4. 检查节点网络配置
sudo iptables -L -n | grep -i docker
ip route show
cat /etc/resolv.conf
```
*目的*：定位是 DNS 解析失败、网络路由问题还是防火墙/代理拦截。

**2. [可选] 将 Pod 调度到其他正常节点**
如果急需启动 Pod，可以为其添加节点选择器或容忍度，避免调度到 `node2`。
```bash
# 为 Deployment/DaemonSet 添加 nodeSelector
kubectl patch deployment <your-deployment> -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/hostname":"master"}}}}}'
```
*依据*：证据表明 `master` 节点网络正常。

### 后续优化
1.  **修复 node2 网络**：根据第一步的诊断结果，修复防火墙规则、路由表或代理配置。
2.  **配置镜像仓库镜像或缓存**：在内网搭建 Docker Registry 镜像或使用 `registry-mirror`，减少对公网的依赖。
3.  **节点网络健康检查**：考虑使用 `NodeLocal DNS` 缓存，并在节点初始化脚本中加入对关键外部服务的连通性检查。
