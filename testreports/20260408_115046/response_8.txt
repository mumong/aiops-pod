## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查并修复节点网络连通性**
登录到问题节点 `node2`，测试到镜像仓库的网络连接。
```bash
# 在节点 node2 上执行
# 测试DNS解析
nslookup registry-1.docker.io
# 测试网络连通性 (如果ICMP未被屏蔽)
ping -c 4 registry-1.docker.io
# 测试TCP 443端口连通性 (Docker Registry使用HTTPS)
timeout 5 bash -c 'cat < /dev/null > /dev/tcp/registry-1.docker.io/443' && echo "Port 443 reachable" || echo "Port 443 unreachable"
# 或使用curl进行更完整的测试
curl -v --connect-timeout 10 https://registry-1.docker.io/v2/
```
*依据*：根因是节点网络问题，必须直接验证。
*目的*：确认是节点出口网络问题、防火墙规则、还是远端服务异常。

**2. [可选] 将Pod调度到其他正常节点**
如果确认是`node2`单点问题，可为问题Pod添加节点选择器或容忍度，避免调度到`node2`。
```bash
# 为Deployment/DaemonSet添加节点亲和性，避开node2 (假设Pod由Deployment控制)
kubectl patch deployment <deployment-name> -n <namespace> -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/hostname": "master"}}}}}'
# 或者给node2打上污点，阻止新Pod调度
kubectl taint nodes node2 network-unreachable=true:NoSchedule
```
*目的*：临时恢复业务，为修复`node2`网络争取时间。
