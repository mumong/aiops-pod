## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查 node2 节点的网络连通性**
登录到 `node2` 节点，测试到公共镜像仓库（如 `registry-1.docker.io`）的网络连接。
```bash
# 在 node2 节点上执行
ping -c 4 registry-1.docker.io
curl -v https://registry-1.docker.io/v2/  # 检查 HTTPS 连接
telnet registry-1.docker.io 443           # 检查端口连通性
```
*目的*：确认外部网络访问是否被阻断。

**2. [关键] 检查 node2 的防火墙和网络策略**
```bash
# 在 node2 节点上执行
sudo iptables -L -n -v | grep -E “(DROP|REJECT)”  # 查看是否有丢弃规则
sudo systemctl status firewalld                    # 检查防火墙服务状态
# 如果是云环境，检查云控制台的安全组/网络ACL规则，确保出站流量（特别是443端口）被允许。
```
*目的*：定位导致连接被重置的具体网络策略。

**3. [临时] 将 Pod 调度到其他正常节点**
为故障的 Deployment/DaemonSet 添加节点选择器或容忍度，避免调度到 `node2`。
```bash
# 例如，为 Pod 添加 nodeSelector，使其调度到 master 节点（如果可调度）
kubectl patch deployment <deployment-name> -n aiops-e2e -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/hostname":"master"}}}}}'
```
*目的*：快速恢复业务，隔离故障节点。

### 后续优化
1.  **配置节点网络监控**：监控节点的网络丢包率、连接重置数等指标。
2.  **统一网络策略管理**：使用 Kubernetes NetworkPolicy 或云平台安全组，确保集群节点具有一致且正确的出站规则。
3.  **使用本地镜像仓库**：搭建内网镜像仓库（如 Harbor），减少对公网的依赖，并提升拉取速度和稳定性。
