## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 检查并修复低内存 limit 的 Deployment（以 memhog 为例）**
```bash
# 查看 memhog Deployment 的内存 limit
kubectl get deployment memhog -n aiops-e2e -o yaml | grep -A 5 -B 5 "resources"

# 将内存 limit 从 200Mi 提升至 512Mi（建议值）
kubectl set resources deployment/memhog -n aiops-e2e --limits=memory=512Mi --requests=memory=256Mi
```
*依据*：`python:3.11-slim` 镜像启动即需 100–200Mi，200Mi 为极限，512Mi 可保障稳定运行

**2. [紧急] 批量检查所有低内存 limit 的 Pod**
```bash
# 查找所有内存 limit ≤ 200Mi 的 Pod
kubectl get pods -A -o jsonpath='{range .items[*]}{.metadata.namespace}{"\t"}{.metadata.name}{"\t"}{.spec.containers[*].resources.limits.memory}{"\n"}{end}' | grep -E "(40Mi|50Mi|100Mi|200Mi)"
```
*输出示例*：`aiops-e2e    memhog-578d9b5ffd-fj5gs    200Mi`  
→ 对每个低 limit 的 Pod 执行 `kubectl set resources deployment/<name> ...`

**3. [可选] 查看当前 Pod 的启动日志（确认是否正常启动）**
```bash
kubectl logs memhog-578d9b5ffd-fj5gs -n aiops-e2e --tail=50
```
*目的*：确认应用是否在启动阶段崩溃（如依赖缺失、端口冲突），排除非 OOM 问题

2. **配置资源请求/限制比例**：`requests=50% limit`，避免调度失败
