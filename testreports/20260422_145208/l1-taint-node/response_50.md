## 📋 集群问题汇总

你的集群有 **2 个异常问题**，都在 `aiops-e2e` 命名空间中：

---

### 🔴 问题一：L0 — Pod 存储卷超限驱逐（EmptyDir 超限）

| 项目 | 内容 |
|------|------|
| **受影响的 Pod** | `logfill-*`（共 **28 个** Evicted Pod） |
| **命名空间** | `aiops-e2e` |
| **所在节点** | `node2` |
| **根因** | Pod 的 EmptyDir 卷 `logs` 写入数据**超过 30Mi 限制**，被 kubelet 驱逐 |
| **事件消息** | `Usage of EmptyDir volume "logs" exceeds the limit "30Mi"` |

**现象**：Pod 使用 `busybox:1.36` 镜像，启动后持续向 `/logs` 写入日志数据，约 **1 分钟内就超过 30Mi 限制**，然后：
1. ⚠️ kubelet 触发 Evicted（驱逐）
2. 🔪 Killing 容器
3. ⏱ 容器运行时的优雅终止超时，出现 `ExceededGracePeriod`

**这是循环问题** — ReplicaSet 反复重建 Pod，Pod 又被反复驱逐（过去 1 小时内发生了 28 次）。

**修复建议**：
- 增大 EmptyDir 的 `sizeLimit`（如改为 100Mi 或更大）
- 或限制 Pod 的日志写入速率
- 或改用 HostPath 或其他持久化存储

---

### 🔴 问题二：L1 — 节点 Taint 导致 Pod 无法调度

| 项目 | 内容 |
|------|------|
| **受影响的 Pod** | `l1-test-nginx-6c69dc7c76-fwzgn` |
| **命名空间** | `aiops-e2e` |
| **状态** | **Pending**（已持续 31 分钟） |
| **根因** | Pod 指定了 `nodeSelector: kubernetes.io/hostname=node2`，但 `node2` 节点上有 `test-unschedulable=true:NoSchedule` **Taint**，且 Pod **没有对应的 Toleration** |
| **调度器消息** | `0/3 nodes are available: 1 node(s) had untolerated taint {test-unschedulable: true}, 2 node(s) didn't match Pod's node affinity/selector` |

**分析**：
- `node2` 资源充足（CPU 8%、内存 17%），节点本身健康（Ready）
- 但 Taint 阻止了没有对应 Toleration 的 Pod 调度
- 其他 2 个节点（master, node1）因 `nodeSelector` 要求 `hostname=node2` 也不匹配
- 导致 **3 个节点都无法使用**

**修复建议**：
- 方案 A：移除 node2 上的 taint：`kubectl taint node node2 test-unschedulable=true:NoSchedule-`
- 方案 B：给 Pod 添加对应 toleration：
  ```yaml
  tolerations:
  - key: "test-unschedulable"
    operator: "Equal"
    value: "true"
    effect: "NoSchedule"
  ```
