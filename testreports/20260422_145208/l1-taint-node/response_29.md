### 🔴 问题一（L0）：EmptyDir 卷超限驱逐

| **节点** | 全部发生在 `node2` (10.2.0.50) |
| **镜像** | `busybox:1.36`（容器名 `logfill`，疑似在持续写入日志填满卷） |

1. Pod 被调度到 node2 → 容器启动（Pulled/Created/Started）
2. 约 **1 分钟后** → `Evicted`，原因明确为 EmptyDir 超限
3. kubelet 发出 `Killing` 指令，且容器未在宽限期内停止（`ExceededGracePeriod`）
4. Deployment ReplicaSet 不断重试创建新 Pod → 循环驱逐

**状态**: 当前该 Deployment 已不存在（可能已被删除），但历史事件清晰记录了全过程。

### 🔴 问题二（L1）：节点 Taint 导致 Pod 无法调度

| 项目 | 内容 |
|------|------|
| **资源** | Pod `l1-test-nginx-6c69dc7c76-fwzgn` (命名空间: `aiops-e2e`) |
| **状态** | **Pending**（持续 23 分钟） |
| **根因** | node2 存在 taint `test-unschedulable=true:NoSchedule`，而 Pod 设置了 `nodeSelector: kubernetes.io/hostname=node2` |
| **调度错误** | `0/3 nodes are available: 1 node(s) had untolerated taint {test-unschedulable: true}, 2 node(s) didn't match Pod's node affinity/selector` |

**证据链**：
1. **node2 的 Taints**: `test-unschedulable=true:NoSchedule` ✅
2. **Pod 的 nodeSelector**: `kubernetes.io/hostname=node2` ✅
3. **Pod 的 Tolerations**: 仅有 `not-ready` 和 `unreachable` 的容忍，**没有**容忍 `test-unschedulable` ✅
4. **调度器结论**: 3 个节点中，node1/master 不匹配 nodeSelector，node2 匹配但不容忍 taint

## 🛠️ 修复建议

### 立即执行（按优先级排序）

**1. [优先] 修复 L1 问题：使 Pod 可以调度到 node2**

*方案 A：移除 node2 上的污点（如果该污点不再需要）*
```bash
kubectl taint node node2 test-unschedulable=true:NoSchedule-
```
*依据*：直接移除阻止 Pod 调度的污点，使 Pod 可以正常调度到 node2。

*方案 B：为 Pod 添加 toleration（如果污点是预期的）*
修改 Deployment `l1-test-nginx` 的 YAML，在 Pod spec 中添加以下 toleration：
```bash
kubectl edit deployment l1-test-nginx -n aiops-e2e
```
在 `spec.template.spec` 下添加：
```yaml
tolerations:
- key: "test-unschedulable"
  operator: "Equal"
  value: "true"
  effect: "NoSchedule"
```
*依据*：显式告诉调度器，这个 Pod 可以容忍 `node2` 上的 `test-unschedulable` 污点。

**2. [可选] 修改 Pod 的 nodeSelector**
如果 Pod 不需要强制调度到 `node2`，可以移除 `nodeSelector` 或修改为其他标签，让调度器自动选择合适的节点。
```bash
kubectl patch deployment l1-test-nginx -n aiops-e2e -p '{"spec":{"template":{"spec":{"nodeSelector":null}}}}'
```
*注意*：此命令会移除整个 `nodeSelector`。
