### 立即执行（按优先级排序）
**1. [优先] 诊断外部网络连通性**
创建一个临时诊断 Pod，测试到 Docker Hub 的网络连接。
```bash
# 运行一个临时 busybox pod 进行网络测试
kubectl run network-test --rm -i --tty --image=busybox --restart=Never -- sh
# 进入容器后执行：
# 测试 DNS 解析
nslookup registry-1.docker.io
# 测试 HTTP 连接 (Docker Hub API)
wget -O- --timeout=5 http://registry-1.docker.io/v2/ || echo "HTTP test failed"
# 测试 HTTPS 连接
wget -O- --timeout=5 https://registry-1.docker.io/v2/ || echo "HTTPS test failed"
```
*目的*：直接验证从集群内部 Pod 访问 Docker Hub 的能力，定位是 DNS、HTTP 还是 HTTPS 层的问题。

**2. [关键] 检查并调整网络策略和防火墙**
检查可能阻止出口流量的 Calico NetworkPolicy 或节点防火墙规则。
```bash
# 查看所有 NetworkPolicy
kubectl get networkpolicy -A
# 查看默认命名空间的 NetworkPolicy (通常影响最广)
kubectl describe networkpolicy -n default
# 如果使用 Calico，可以查看全局网络策略
kubectl get globalnetworkpolicy -A
```
*依据*：如果存在过于严格的出口（Egress）策略，会阻止 Pod 访问外部网络。

### 后续优化
1.  **配置镜像拉取超时和重试**：在 Pod Spec 中为 `imagePullPolicy` 配置更长的 `imagePullSecrets` 或调整 kubelet 的 `--image-pull-progress-deadline` 参数（需修改节点配置）。
2.  **使用内部镜像仓库**：搭建私有镜像仓库（如 Harbor），将常用镜像缓存到内网，避免依赖不稳定的公网。
3.  **配置网络代理**：如果集群处于受限网络环境，需要为 Docker 和 Kubelet 配置正确的 HTTP/HTTPS 代理。
