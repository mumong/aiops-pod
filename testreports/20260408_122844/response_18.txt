## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 为Pod添加对应的污点容忍**
如果已知Pod名称和命名空间，在其Deployment/DaemonSet/Pod的spec中添加容忍：
```yaml
tolerations:
- key: "test-unschedulable"
  operator: "Equal"
  value: "true"
  effect: "NoSchedule"
```
或通过补丁命令（替换 `<deployment-name>` 和 `<namespace>`）：
```bash
kubectl patch deployment <deployment-name> -n <namespace> --type='json' -p='[{"op": "add", "path": "/spec/template/spec/tolerations", "value": [{"key": "test-unschedulable", "operator": "Equal", "value": "true", "effect": "NoSchedule"}]}]'
```
*依据*：直接解决调度失败的根本原因。

**2. [备选] 移除节点的污点**
如果该污点是测试残留或无意义的，可以直接移除（替换 `<node-name>`，如 `master`）：
```bash
kubectl taint nodes <node-name> test-unschedulable:true-
```
*注意*：移除master节点的污点可能导致普通Pod被调度到控制平面，影响稳定性，请谨慎操作。

### 后续优化
1.  **污点管理规范**：建立污点的申请、添加、移除流程，避免随意添加影响调度的污点。
2.  **Pod容忍设计**：在部署工作负载时，根据其特性（如是否为系统组件）预先设计好容忍策略。
3.  **事件监控**：配置告警，监控长时间处于 `Pending` 状态的Pod。
