## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 诊断网络连通性**
在任意一个集群节点上执行以下命令，测试到 Docker Hub 的连通性：
```bash
# 测试DNS解析
nslookup registry-1.docker.io
# 测试网络连通性 (如果ICMP未被屏蔽)
ping -c 4 registry-1.docker.io
# 测试HTTPS端口访问 (最可靠)
curl -v --connect-timeout 10 https://registry-1.docker.io/v2/
```
*目的*：确认是网络不通、DNS解析失败还是HTTPS端口被阻。

**2. [关键] 检查故障Pod详情**
获取一个处于`ImagePullBackOff`状态的Pod的详细事件，以获取具体错误码：
```bash
# 请将 <pod-name> 替换为实际的故障Pod名称，例如 nginx-xxx
kubectl describe pod <pod-name> -n <namespace> | grep -A 10 -B 5 "Events:"
```
*目的*：根据错误信息（如 `net/http: request canceled`、`x509: certificate`等）进一步定位。

**3. [临时] 使用替代镜像或内部仓库**
如果业务紧急，可以修改Deployment，使用可访问的镜像源，例如阿里云镜像加速器或企业内部仓库：
```bash
# 例如，将 nginx 镜像替换为阿里云镜像
kubectl set image deployment/<deployment-name> <container-name>=registry.cn-hangzhou.aliyuncs.com/google_containers/nginx:latest
```

### 后续优化
1.  **配置镜像仓库Mirror或加速器**：在容器运行时（如Docker或Containerd）配置镜像加速器，避免依赖单一外部源。
2.  **部署内部镜像仓库**：搭建 Harbor 或 Nexus 等私有仓库，将常用基础镜像同步至内网。
3.  **配置网络出口监控**：对集群节点的出口流量进行监控，便于快速定位类似网络问题。
