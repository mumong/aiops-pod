## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 诊断具体的镜像拉取错误**
```bash
# 获取处于 ImagePullBackOff 状态的 Pod 详情
kubectl get pods --all-namespaces --field-selector=status.phase!=Running
# 针对其中一个故障 Pod 获取详细事件和状态
kubectl describe pod <pod-name> -n <namespace>
```
*目的*：确认错误详情、涉及的镜像仓库地址和所在节点。

**2. [关键] 测试节点到镜像仓库的网络连通性**
假设镜像仓库为 `registry-1.docker.io`，在**故障 Pod 所在的节点**上执行：
```bash
# 进入节点（需有节点访问权限）
# 测试 DNS 解析
nslookup registry-1.docker.io
# 测试 TCP 连通性（通常使用 443 端口）
telnet registry-1.docker.io 443
# 或使用 curl 测试 HTTPS 连接
curl -v https://registry-1.docker.io/v2/
```
*目的*：直接验证出站网络是否畅通。

**3. [可选] 临时解决：使用本地镜像或更改镜像拉取策略**
如果存在本地可用镜像，可以更新部署：
```bash
kubectl set image deployment/<deployment-name> <container-name>=<local-image:tag>
```
或将镜像拉取策略改为 `IfNotPresent`（仅适用于节点上已存在镜像的情况）：
```bash
kubectl edit deployment/<deployment-name>
# 在 spec.template.spec.containers 下添加： imagePullPolicy: IfNotPresent
```

### 后续优化
1.  **配置镜像仓库代理或镜像缓存（如 Harbor, Docker Registry）**：减少对公网的依赖，加速拉取并提高稳定性。
2.  **审查节点网络策略和防火墙规则**：确保 `kubelet` 可以访问所需的镜像仓库端口（通常是 443 或 5000）。
3.  **配置 Pod 的 `imagePullSecrets`**：如果使用的是私有仓库，确保 Secret 配置正确且未过期。
4.  **监控**：对镜像拉取错误（`ImagePullBackOff`）设置告警。
