## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [优先] 定位并检查仍在失败的Pod**
首先确认哪个命名空间和哪个Pod目前仍有问题。
```bash
# 查看所有命名空间中状态异常的Pod
kubectl get pods --all-namespaces --field-selector=status.phase!=Running | grep -v Completed
```
**2. [关键] 获取故障Pod的详细事件**
一旦找到状态为`ImagePullBackOff`或`ErrImagePull`的Pod，立即查看其事件。
```bash
kubectl describe pod <故障Pod名称> -n <Pod所在命名空间>
```
*目的*：从事件消息中获取具体错误原因，例如：
- `“failed to pull image \"registry.com/image:tag\": rpc error: code = Unknown desc = ..."`
- `“pull access denied for <image>, repository does not exist or may require 'docker login'”`

**3. [根据错误信息采取行动]**
- **若镜像不存在或标签错误**：修正Deployment/DaemonSet等资源中的镜像名称和标签。
    ```bash
    kubectl set image deployment/<部署名称> <容器名>=<正确镜像路径:标签> -n <命名空间>
    ```
- **若认证失败**：检查并创建正确的`imagePullSecret`。
    ```bash
    # 查看现有secret
    kubectl get secrets -n <命名空间>
    # 创建docker-registry类型的secret (需提前登录)
    kubectl create secret docker-registry <secret名称> \
      --docker-server=<仓库地址> \
      --docker-username=<用户名> \
      --docker-password=<密码> \
      -n <命名空间>
    # 更新Pod模板使用该secret
    kubectl patch deployment <部署名称> -p '{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"<secret名称>"}]}}}}' -n <命名空间>
    ```
- **若网络不通**：检查节点防火墙、网络策略（NetworkPolicy）或代理设置。

### 后续优化
1.  **规范镜像管理**：使用内部镜像仓库或可信的公共仓库，并固定镜像标签（避免使用`latest`）。
2.  **配置预拉取镜像**：在节点初始化脚本中预拉取基础镜像，减少运行时拉取失败概率。
3.  **监控告警**：配置对`Pod`状态`ImagePullBackOff`和`ErrImagePull`的监控告警。
