## 🛠️ 修复建议
### 立即执行（按优先级排序）
**1. [核心] 检查并修复节点出站网络策略**
您需要登录到**节点（node1, node2）** 的宿主机（或联系集群管理员），检查防火墙规则（如 `iptables`, `firewalld`）或云服务商的安全组配置。
*   **检查 iptables 规则（在节点上执行）**:
    ```bash
    sudo iptables -L -n -v | grep DROP
    sudo iptables -L OUTPUT -n -v
    ```
*   **检查 firewalld 规则（在节点上执行）**:
    ```bash
    sudo firewall-cmd --list-all
    ```
*   **检查代理配置（在节点上执行）**:
    ```bash
    cat /etc/environment | grep -i proxy
    cat /etc/systemd/system/docker.service.d/*.conf | grep -i proxy  # 如果是 Docker 运行时
    ```
*   **云服务商（如 GCP, AWS, Azure）**：检查 VPC 的**网络防火墙规则**或**安全组出站规则**，确保允许集群节点向 `0.0.0.0/0` 的 TCP 443 端口出站。

**2. [替代方案] 配置镜像仓库代理/镜像仓库（如果无法打通直连）**
如果公司策略不允许节点直接访问外网，可以为您的 Kubernetes 集群配置一个**私有镜像仓库**（如 Harbor, Nexus, AWS ECR）作为代理。
*   **在 containerd 配置中（常见于 k8s >= 1.24）**：
    编辑 `/etc/containerd/config.toml` 文件，添加 `[plugins."io.containerd.grpc.v1.cri".registry.mirrors]` 配置。
*   **配置示例**:
    ```toml
    # /etc/containerd/config.toml 中的部分内容
    [plugins."io.containerd.grpc.v1.cri".registry]
      [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
        [plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
          endpoint = ["https://your-proxy-repo.com/v2/"]  # 替换为您的代理仓库地址
        [plugins."io.containerd.grpc.v1.cri".registry.mirrors."registry.k8s.io"]
          endpoint = ["https://your-proxy-repo.com/v2/"]  # 替换为您的代理仓库地址
    ```
    配置修改后，在所有节点上重启 containerd:
    ```bash
    sudo systemctl restart containerd
    ```

### 后续优化
1.  **配置 HPA 与 PDB**：确保生产应用有恰当的 HPA 自动扩缩容和 PDB 预算，避免单点故障。
2.  **实施 Pod 资源限制**：避免应用无限制使用资源。如在 Deployment 中配置 `resources.limits.memory` 和 `resources.requests.memory`。
3.  **镜像管理**：优先使用私有仓库，或在 CI/CD 流程中预先将镜像推送至私有仓库，减少对公共仓库的外部依赖。
