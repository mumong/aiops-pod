## 四项指标怎么测

本次测试 c01～c11，每个 Case 50 次。脚本根据真实诊断报告、节点记录和 Evidence 归档评分；以下解释原始评分，不混入人工审查结果。

| 指标 | 测试方式 | 单次计算 |
|---|---|---|
| MTTR | 记录一次成功诊断到最终报告的耗时，优先使用服务端耗时 | `elapsed_seconds`；不是修复恢复时间，不含部署与清理 |
| 根因准确率 | 从报告的根因结论提取内容，按该 Case 的关键词、同义词、否定和冲突规则匹配 | 本次均为单主根因：通过 100%，未通过 0%；不是全文出现异常词就通过 |
| Runbook 覆盖率 | 从报告“Runbook 参考”和明确的结构化选择字段提取手册 ID，与期望清单比较 | 命中的期望 Runbook 数 ÷ 期望 Runbook 数；例如命中 1/2 得 50% |
| 证据完整度 | 读取 Evidence Plan 的计划项数与已完成项数，不数报告事实或工具调用次数 | `plan_collected / plan_total`；例如完成 4/5 得 80% |

### 统一汇总方式

**先算每次得分 → 在每个 Case 内求算术平均 → 再对各 Case 等权求算术平均。**

例如两次完整度为 80% 和 60%，均值就是 **70%**，不合并两次的完成项与计划项再计算。仅当同一次诊断包含多个 lane 时，先汇总这些 lane 的完成项／计划项，得到这一次的得分。

请求失败单独统计，不进入质量均值；证据缺失记 N/A，不按 100% 处理。根因、Runbook、证据三项通过阈值为 **≥70%**，MTTR 为 **<15 分钟**。

### 读分数时注意

- 根因是文本规则评分，可能误判，不等于人工确认。
- Runbook 多查无关手册不扣分，覆盖高不代表使用正确。
- 证据分数采用 Agent 归档的完成计数，评分器不独立重建匹配关系；衡量的是“自己的计划完成多少”，不是理想证据是否齐全。
- 重试时 MTTR 只计最终成功尝试，不等于全部等待时间。

原文看每次运行的 `report.md`，评分明细看 `score.json`，计划和工具结果看 `evidence.archive.json`；本次规则快照与汇总数据见 [stats.json](stats.json)。
