## 🛠️ 修复建议

### 立即执行（按优先级排序）

**1. [优先] 检查节点资源使用情况**
```bash
kubectl describe node <node_name>
```
*目的*：查看节点的 CPU、内存、磁盘使用情况，判断是否资源不足。

**2. [优先] 检查节点驱逐事件**
```bash
kubectl describe pod <evicted_pod_name> -n aiops-e2e
```
*目的*：确认 Pod 被驱逐的具体原因（如 OOMKilled、DiskPressure、NodePressure 等）。

**3. [可选] 检查 PVC 状态**
```bash
kubectl get pvc -n aiops-e2e
```
*目的*：确认是否因存储卷不足导致 Pod 被驱逐。

### 后续优化

1. **清理或扩缩容**：
   - 如果是资源不足，可考虑清理不必要的 Pod 或增加节点资源。
   - 使用 `kubectl top node` 查看资源瓶颈（需 Heapster/Metrics Server 支持）。
2. **优化资源限制**：
   - 适当增加节点资源限制，或调整 Pod 的资源请求/限制。
3. **配置驱逐策略**：
   - 通过修改 kubelet 配置调整驱逐阈值（如内存、磁盘压力阈值）。
4. **监控告警**：
   - 配置监控系统（如 Prometheus + Alertmanager）对节点资源和 Pod 状态进行告警。
