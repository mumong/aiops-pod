## 🎯 根因结论
**结论**: `aiops-e2e/logfill` Deployment 的 Pod 因 EmptyDir 存储卷超限被 kubelet 驱逐。Pod 配置了 `logs` 卷的 SizeLimit 为 30Mi，但实际使用超过此限制，触发 kubelet 驱逐机制。

## 🛠️ 修复建议
1. **立即修复**：检查 logfill 应用的日志生成逻辑，减少日志量或增加 SizeLimit
   ```yaml
   # 修改 Deployment 配置
   volumes:
   - name: logs
     emptyDir:
       sizeLimit: 100Mi  # 增加限制
   ```

2. **清理异常 Pod**：
   ```bash
   kubectl delete pods -n aiops-e2e -l app=logfill --field-selector=status.phase!=Running
   ```

3. **监控磁盘使用**：master 节点磁盘使用率 82.13% 接近警戒线，建议清理或扩容

4. **检查 crash-demo-exit**：该 Pod 持续重启81次，可能是测试残留，建议删除：
   ```bash
   kubectl delete pod crash-demo-exit -n default
   ```
