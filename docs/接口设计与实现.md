## 接口设计与实现（HTTP API）

本文是 `robusta/` 子项目对外 API 的**完整接口清单 + 设计约定 + 实现映射**文档，面向：

- 对接方：前端、ChatOps、脚本（curl）、平台集成
- 开发者：要扩展接口、排查流式输出/联邦查询/工具集问题

实现原则（代码中已体现）：
- **简单优先**：主入口 `GET /ask?q=...` 即可用
- **流式优先**：默认 `stream=true`，避免长任务无响应
- **统一输出协议**：`format=text|sse` 两种外观，底层尽量基于统一的“内部事件”

---

## 1. 服务信息

### 1.1 进程入口

- **启动脚本**：`robusta/run.py`
- **FastAPI 应用**：`robusta/app/main.py`
- **路由注册**：`robusta/app/api/routes.py::register_routes(app)`

### 1.2 端口与基础地址

默认监听：
- `API_HOST=0.0.0.0`
- `API_PORT=8000`

常见访问：
- `http://HOST:8000/ask`

## 2. 输出格式与协议约定

### 2.1 文本流（format=text）

HTTP 响应：
- `Content-Type: text/plain; charset=utf-8`
- body 为逐行/逐块输出的可读文本（适合 curl）

推荐调用：

```bash
curl -N "http://HOST:8000/ask?q=磁盘满了怎么清理&format=text"
```

### 2.2 SSE（format=sse）

HTTP 响应：
- `Content-Type: text/event-stream`
- 采用标准 SSE 格式：`event: <type>\n data: <json>\n\n`

SSE 消息生成函数：
- `app/core/holmes/streaming.py::create_sse_message_cn(event_type, data)`

推荐调用：

```bash
curl -N "http://HOST:8000/ask?q=Pod一直重启&format=sse"
```

### 2.3 SSE 事件类型（单集群 /ask）

当 `format=sse` 且使用默认 Holmes agentic loop（`USE_WORKFLOW=false`）时，事件来源主要是：
- `app/core/holmes/query_stream.py`
- `app/core/holmes/event_mapper.py`（将 Holmes StreamEvents 映射为统一内部事件）

事件集合（常见）：
- `run_start`：开始执行（含问题、时间戳、初始化耗时等）
- `tool_start`：开始调用某工具（含 iteration/tool_name/tool_id）
- `tool_result`：工具返回（含 status、duration、result_preview、artifact_id 等）
- `ai_message`：LLM 输出内容片段
- `ai_reasoning`：LLM 推理（如果上游提供）
- `iteration_end`：一次迭代结束（含 token usage/耗时）
- `history_compacted`：对话历史压缩（如果发生）
- `blocked`：策略阻塞（需要用户批准的操作）
- `error`：执行错误
- `final`：最终答案（保证一定会发出）
- `run_end`：结束
- `stream_end`：兼容事件（旧客户端可能依赖）

> 说明：`final` 的内容会经过“最终答案选择策略”，避免 DSML 草稿/阻塞片段被当成最终答案。实现见 `app/core/holmes/event_schema.py`。

### 2.4 长输出截断与全文获取（artifact）

当工具输出过长时：
- `tool_result.result_preview` 为截断预览
- `tool_result.result_truncated=true` 且可能携带 `artifact_id`

可通过：
- `GET /artifacts/{artifact_id}` 获取全文（内存缓存，带 TTL）

实现：
- `app/core/holmes/artifacts.py`（ArtifactStore）
- `app/api/routes.py::get_artifact`

## 4. 单集群查询接口

### 4.1 GET `/ask`

**用途**：单集群诊断/查询统一入口。

**Query 参数**：
- `q`（string，必填）：问题
- `stream`（bool，默认 true）：是否流式输出
- `format`（string，默认 `text`）：`text` 或 `sse`
- `max_steps`（int，默认 20，范围 1-100）：最大工具调用迭代步数

**返回**：
- 当 `stream=true`：
  - `format=text` → `text/plain` 流
  - `format=sse` → `text/event-stream`
- 当 `stream=false`：
  - `text/plain`，内容是最终答案字符串

**实现映射**：
- 路由：`app/api/routes.py::ask_get`
- 流式：`app/api/routes.py::_stream_response` → `HolmesService.execute_query_stream(...)`
- 非流式：`app/api/routes.py::_sync_response` → `HolmesService.execute_query(...)`

**示例**：

```bash
# 默认（流式 text）
curl -N -G "http://HOST:8000/ask" --data-urlencode "q=Pod一直重启怎么办"

# SSE（推荐用于程序化消费）
curl -N -G "http://HOST:8000/ask" --data-urlencode "q=Pod一直重启怎么办" --data-urlencode "format=sse"

# 非流式（一次性结果）
curl -G "http://HOST:8000/ask" --data-urlencode "q=查看集群状态" --data-urlencode "stream=false"
```

### 4.2 POST `/ask`

**用途**：同 `/ask`，但用表单参数（更适合复杂客户端或避免 URL 长度限制）。

**Form 参数**：`q/stream/format/max_steps`（含义同 GET）。

**实现映射**：`app/api/routes.py::ask_post`

### 4.3 GET `/q/{question:path}`

**用途**：`/ask` 的“路径参数”别名，适合更短的 URL 风格。

**注意**：特殊字符需要 URL 编码。

**实现映射**：`app/api/routes.py::ask_path`

## 5. 兼容旧接口（v1）

### 5.1 POST `/api/v1/query`

**请求体**：JSON（dict）
- `question`（string）
- `max_steps`（int，可选）

**返回**：非流式（纯文本）。

**实现映射**：`app/api/routes.py::legacy_query` → `_sync_response(...)`

### 5.2 POST `/api/v1/query/stream`

**请求体**：JSON（dict）
- `question`（string）
- `output_format`（string，默认 text；兼容字段名）
- `max_steps`（int，可选）

**返回**：流式（text 或 SSE）。

**实现映射**：`app/api/routes.py::legacy_query_stream` → `_stream_response(...)`

## 6. 联邦多集群接口

### 6.1 GET/POST `/federation/ask`（v1 并发聚合）

**用途**：并发查询所有已配置子集群，汇总后合成统一报告（流式 text）。

**参数**：
- `q`（必填）：问题
- `max_steps`（默认 30）：每个子集群最大步数
- `conclusion_max_tokens`（默认 8192）：子集群结论 token 上限（0 可表示不限）

**返回**：
- `text/plain; charset=utf-8` 流

**实现映射**：
- 路由：`app/api/routes.py::federation_ask_get / federation_ask_post`
- 调用：`service.federation_coordinator.ask_stream(...)`

**未启用时行为**：
- 返回一段可读文本提示如何在配置中启用（不会抛 500）。

### 6.2 GET/POST `/federation/ask/v2`（v2 Agent-to-Agent）

**用途**：由主 Agent 通过 Tool Calling 决定查询哪些子集群，支持：
- 指定集群（“查询 cluster-24 的 CPU”）
- 多集群对比（“对比 main 和 cluster-24 的 CPU”）
- 不同集群不同问题（“main 的 memory + cluster-24 的 cpu”）

**参数**：
- `q`（必填）
- `max_steps`（默认 30）：主 Agent 的 tool-calling loop 最大步数

**返回**：
- `text/plain; charset=utf-8` 流（逐块输出）

**实现映射**：
- 路由：`app/api/routes.py::_federation_agent_stream_response`
- Agent：`app/core/federation/agent.py::FederationAgent.ask_stream`
- 工具集：`app/core/federation/toolset.py::FederationToolset`
  - `list_clusters`
  - `query_cluster`

**副产物**：
- v2 过程中每个子集群的完整报告会落盘到 `reports/*.md`（便于追溯/审计）

## 7. 运行态与辅助接口

### 7.1 GET `/health`

**用途**：探测服务是否初始化完成与当前状态。

**返回（示例字段）**：
- `status`: `healthy|initializing|unhealthy|uninitialized`
- `config_loaded`: bool
- `ai_initialized`: bool
- 可选：`error/started_at`

**实现映射**：`app/api/routes.py::health_check` → `HolmesService.health_check()`

### 7.2 GET `/tools`

**用途**：列出所有已注册工具名与 toolset 状态（排障/可观测）。

**实现映射**：`app/api/routes.py::list_tools` → `HolmesService.get_tools_info()`

### 7.3 GET `/tools/detail`

**用途**：输出更详细的 toolset → tools 列表，并尽量返回 tool schema/描述（用于二次开发）。

**实现映射**：`app/api/routes.py::list_tools_detail` → `HolmesService.get_tools_detail()`

### 7.4 GET `/runbooks`

**用途**：列出合并后的 runbook catalog 条目（`id/description/link`）。

**实现映射**：`app/api/routes.py::list_runbooks` → `service.merged_catalog`

### 7.5 GET `/artifacts/{artifact_id}`

**用途**：获取 tool_result 被截断的全文（内存缓存，带 TTL）。

**状态码**：
- 200：返回全文
- 404：artifact 不存在或已过期

**实现映射**：`app/api/routes.py::get_artifact` → `ArtifactStore.get()`

### 7.6 GET `/api/v1/mcp/status`

**用途**：查看“本地 auto-start MCP 管理器”的运行态。

**说明**：这不是远程 MCP 连接状态；它只反映本进程启动的本地脚本子进程（如果启用）。

**实现映射**：`app/api/routes.py::get_mcp_status` → `app/core/mcp/manager.py::get_mcp_manager().get_status()`

### 7.7 GET `/reports` 与 `/reports/{filename}`

**用途**：查看联邦 v2（A2A）落盘的子集群诊断报告。

`GET /reports` 参数：
- `cluster`（可选）：按文件名前缀过滤（`{cluster}_...`）
- `limit`（默认 50，1-500）

`GET /reports/{filename}`：
- 返回报告文本
- 做了路径穿越防护（仅允许访问 `reports/` 子目录内的文件）

实现映射：
- `app/api/routes.py::list_reports / get_report`

## 8. 错误与异常语义约定

### 8.1 同步模式（stream=false）

- 成功：200 + `text/plain`（最终答案）
- 失败：通常为 500（FastAPI `HTTPException`），`detail` 为错误信息

### 8.2 流式模式（stream=true）

- 默认不会中断连接抛出结构化 JSON 错误；而是把错误作为文本块或 SSE `error` 事件输出
- SSE 模式下会发出：
  - `event: error`（含 `{success:false,error:"..."}` 或统一内部事件的 error 字段）

### 8.3 联邦未启用

`/federation/*` 在未启用时：
- 返回“可读提示文本”（而不是 500），指导在 `config.yaml federation.enabled=true` 及配置子集群。

## 9. 实现导读（从接口跳到代码）

### 9.1 路由与响应

- 路由定义与大部分响应行为：`app/api/routes.py`
- `StreamingResponse` headers：
  - `Cache-Control: no-cache`
  - `Connection: keep-alive`
  - `X-Accel-Buffering: no`（避免 Nginx 缓冲影响流式）

### 9.2 单集群执行入口

- `HolmesService.execute_query(...)`：同步
- `HolmesService.execute_query_stream(...)`：流式（内部根据 `USE_WORKFLOW` 分叉）

### 9.3 流式实现（text/sse）

- `app/core/holmes/query_stream.py`
  - `execute_query_stream_text`
  - `execute_query_stream_sse`
- `app/core/holmes/event_mapper.py`
  - `iter_internal_events`：Holmes StreamEvents → 内部事件协议
- `app/core/holmes/event_schema.py`
  - `select_final_answer`：选择最终答案，避免 DSML/草稿被当结果

### 9.4 联邦实现（v2 A2A）

- `app/core/federation/agent.py`：tool-calling loop + 并发 query_cluster + 最终流式生成
- `app/core/federation/toolset.py`：`list_clusters/query_cluster` 两个工具
- `app/core/federation/registry.py`：子集群配置数据结构
