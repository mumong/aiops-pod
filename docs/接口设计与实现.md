## 接口设计与实现

本文只描述当前正式接口。

## 1. 设计原则

- `/ask` 只做诊断
- `/query` 只做查询
- 联邦接口与单集群接口一一对应
- 默认流式输出，便于长任务可观测
- 兼容接口保留，但不作为正式入口推荐

## 2. 正式接口总览

### 单集群

| 方法 | 路径 | 用途 |
|------|------|------|
| GET/POST | `/ask` | 单集群诊断 |
| GET/POST | `/query` | 单集群查询 |

### 联邦

| 方法 | 路径 | 用途 |
|------|------|------|
| GET/POST | `/federation/ask` | 多集群广播诊断 |
| GET/POST | `/federation/query` | 多集群广播查询 |
| GET/POST | `/federation/ask/v2` | 多集群 Agent 诊断 |
| GET/POST | `/federation/query/v2` | 多集群 Agent 查询 |

### 辅助

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/health` | 健康检查 |
| GET | `/tools` | 工具列表 |
| GET | `/tools/detail` | 工具详情 |
| GET | `/runbooks` | runbook 列表 |
| GET | `/reports` | 已保存报告列表 |
| GET | `/reports/{filename}` | 查看单份报告 |
| GET | `/artifacts/{artifact_id}` | 查看被截断的长输出全文 |
| POST | `/remediation/approve` | 修复流程人工审批 |
| GET | `/api/v1/mcp/status` | MCP 运行状态 |

### 兼容入口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/q/{question:path}` | 历史快捷别名，不建议作为正式入口 |
| POST | `/api/v1/query` | 兼容旧接口 |
| POST | `/api/v1/query/stream` | 兼容旧接口 |

## 3. 通用参数

### `/ask` 与 `/query`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `q` | string | 必填 | 用户问题 |
| `stream` | bool | `true` | 是否流式输出 |
| `format` | string | `text` | `text` 或 `sse` |
| `max_steps` | int | `20` | 最大执行步数 |
| `remediate` | bool | `false` | 是否在诊断后进入人工审批修复流程，仅 `/ask` 支持 |

说明：

- `q` 推荐使用 `--data-urlencode`
- `stream=false` 时返回完整文本
- `format=sse` 适合前端消费
- `remediate=true` 必须配合 `stream=true`，审批方式见 [修复执行与人工审批使用说明](/root/huhu/agent/combine-aiops-mcp/robusta/docs/remediation-usage.md)

### `/federation/ask` 与 `/federation/query`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `q` | string | 必填 | 用户问题 |
| `max_steps` | int | `30` | 每个子集群的最大执行步数 |
| `conclusion_max_tokens` | int | `8192` | 子集群结论最大 token |

### `/federation/ask/v2` 与 `/federation/query/v2`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `q` | string | 必填 | 用户问题 |
| `max_steps` | int | `30` | 主 Agent 的最大执行步数 |

## 4. `/ask`

### 语义

适合：

- 我的集群有什么问题
- 为什么这个 Pod 一直重启
- 帮我分析一下当前异常

### 工作流

```text
layer -> evidence -> rca -> conclusion
```

### 示例

```bash
curl --no-buffer -G "http://HOST:30800/ask" \
  --data-urlencode "q=我的集群有什么问题？"
```

### 返回特点

- 包含节点进度
- 包含性能统计
- 包含诊断追踪
- 可能包含核心/参考 runbook

## 5. `/query`

### 语义

适合：

- CPU / 内存 / 磁盘 / 网络是多少
- 某个对象状态是什么
- 某类资源列表

### 工作流

```text
layer -> conclusion
```

### 示例

```bash
curl --no-buffer -G "http://HOST:30800/query" \
  --data-urlencode "q=集群 CPU 和内存使用率是多少，具体到每个 node"
```

### 返回特点

- 不走 evidence / rca
- 以结构化表格为主
- 重点是 `query_result`

## 6. 联邦接口

### `/federation/ask`

广播式诊断。

- 对所有已启用子集群发同一个诊断问题
- 适合统一巡检、统一比对

```bash
curl --no-buffer -G "http://HOST:30800/federation/ask" \
  --data-urlencode "q=现在所有集群分别有什么问题？"
```

### `/federation/query`

广播式查询。

- 对所有已启用子集群发同一个查询问题

```bash
curl --no-buffer -G "http://HOST:30800/federation/query" \
  --data-urlencode "q=各集群 CPU 使用率是多少"
```

### `/federation/ask/v2`

Agent-to-Agent 诊断。

- 主 Agent 决定查哪些子集群
- 可支持不同集群不同语义

```bash
curl --no-buffer -G "http://HOST:30800/federation/ask/v2" \
  --data-urlencode "q=main 和 cluster-24 现在分别有什么问题？"
```

### `/federation/query/v2`

Agent-to-Agent 查询。

```bash
curl --no-buffer -G "http://HOST:30800/federation/query/v2" \
  --data-urlencode "q=对比 main 和 cluster-24 的 CPU 使用率"
```

## 7. 输出格式

### `format=text`

- 适合终端、curl、人直接阅读

### `format=sse`

- 适合前端或程序化消费
- 按事件流返回

## 8. 关键辅助接口

### `/health`

```bash
curl http://HOST:30800/health
```

典型返回：

- `healthy`
- `initializing`
- `unhealthy`

### `/tools`

查看已加载工具名称。

### `/runbooks`

查看当前 catalog 中可用的 runbook。

### `/reports`

查看联邦模式下落盘保存的报告。

## 10. 当前口径

文档中所有“正式入口”都以以下设计为准：

- `/ask` = 诊断
- `/query` = 查询
- 联邦接口与单集群接口保持同语义

不再把“查询和诊断混在一个入口里”作为主文档推荐方案。
