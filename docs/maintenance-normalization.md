# 三项目规范化：范围、基线与验收

## 目标与兼容边界

按 2026-09-24 附件要求审查 AIOps、MCP、前端。核心约束是保持功能、逻辑和效果，
不是重设计诊断流程。先补行为特征测试，再提取职责与复用；保留 API/SSE、工具
schema/描述/输出、提示词文本、会话存储、审批与部署配置等对外契约。

Python 使用 PEP 8 的 snake_case 模块/变量和 `#`/docstring，TypeScript 使用现有
组件命名与驼峰约定；不将 Go 专用文件名和注释规则机械用于其他语言。
99 列作为新增/修改代码的格式目标，不折行改变提示词、命令或协议内容。
IoC 指依赖注入，不是反向代理；在已有可替换依赖边界引入抽象，不为抽象添加层级。

不把附件后半段 Telegram 事件建模讨论加入本项目。许可证与仓库角色权限需要
所有者授权；不得自行更换许可证或修改远程项目成员/保护分支。
