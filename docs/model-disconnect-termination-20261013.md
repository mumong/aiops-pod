# 模型断流终止运行

用户确认：模型流断开直接结束本次运行并显示错误，不重试、不继续串行取证或生成部分成功报告。

## 实现

- 模型调用层将可识别的 SDK 断流/连接异常提升为 `ModelStreamInterrupted`，保留原始异常链供日志排查。
- 移除断流后非流式重试；模型客户端禁用 SDK 请求自动重试。
- 路由阶段同样传播断流错误；执行器现有 SSE `error` 路径负责提示，后续节点不启动。
- 并发分支通过独立停止信号停止后续工作，向父工作流抛出异常；不把故障标为用户取消或正常部分完成。
- 分组执行器在消费者异常退出时取消待执行 Future，不等待已发出的请求才提示错误。已在途请求不保证立即物理中止，已完成操作不回滚。
- 修复规划收到工作流错误时保存失败状态和可读错误，不启动执行。
- 不改变普通工具错误、步数上限和非断流异常的现有处理，不新增故障场景判断。

## 验证与发布范围

测试覆盖无工具请求、工具调用前后断流、不重复请求、真实 LangGraph 节点停止、并发停止及 SSE 仅错误无最终报告，以及修复/API 回归。断流通过注入模拟，不主动破坏真实模型服务或执行集群修复。

验证结果：相关回归 490 项通过（29 个既有弃用警告）。新生产镜像隔离运行真实 SDK + LangGraph + SSE 执行器，本地 HTTP 服务注入相同断流错误：请求次数 1、节点仅 request_router/layer、错误事件 1、无 final 事件。该验证不是主动断开线上模型服务，也不是完整真实诊断验收。

发布 `11.0.224-stop-on-disconnect-20261013` 基于线上 `.223`，仅覆盖 client、errors、request_router、autonomous_parallel、group_runner、repair jobs 六个模块。未夹带本地未上线 handoff 改动；前端版本保持不变。
