# 分阶段交接验证记录（2026-10-14）

## 已交付设计

- 定位保留异常/待核实对象及范围覆盖，不把全部正常 Pod 明细放入下游保护区。
- 分支只接收自己的对象、问题、引用和范围，不复制定位工具历史或兄弟分支内容。
- 采证输出普通分析和最多 8 条关键事实、6 条未知项、6 个 Runbook 引用。RCA 的小型保护区只包含本组定位与采证交接；原始材料仍按普通策略压缩、归档。
- RCA 发布本组完整报告和结构化成果。conclusion 只接收小型结果索引，预算不足时分批汇总索引；程序拼接全部正式报告，不让总览模型重写各组结果。
- 总览非断流错误不会抹去分组报告。模型服务断流仍按现有约定终止运行，不隐藏错误。
- 修复按组读取 RCA 成果、关键事实、未知项和引用，不从总览重新提取异常；未修改审批和命令执行策略。
- RCA 由代码生成 `evidence_index_ref`，指向本组真实工具归档目录；即使模型引用写成描述，仍能定向找回原始证据。目录正文不进入保护区。
- 前端显示总览和独立折叠卡片，每次展示 10 组；复制报告保留完整内容。历史会话恢复后保留分组展示。

## 边界和复验方法

- 100 组测试是构造的交接/总览预算/前端展示测试，不是 100 个真实异常的全链路负载测试；定位输出容量、模型限流、归档容量和浏览器 localStorage 仍有上限。
- 保护的是 Agent 选出的关键事实及代码生成的归档入口，不保证模型永不漏选或判断永远正确。全量原始结果没有被删除。
- 定位仍可自主查询，第一轮调用 19 次工具，存在和分支重复查询的效率空间；本次不加入固定流程或按故障类型硬裁剪。
- 恢复后的服务健康、审批执行和回滚不是本次测试结论；修复只验证规划和组内反馈。
- `scripts/verify_stage_handoff.py <运行归档目录>` 检查实际分支/总览输入；`scripts/verify_repair_handoff_live.py --help` 是显式启用、禁止执行的真实规划检查。
- 前端 `tests/live-stage-handoff.browser.py` 用于真实只读诊断；`tests/diagnosis-history.browser.py` 用于已有结果恢复和 100 组构造回放。
