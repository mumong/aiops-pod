- 不新增故障特判、不强制 Agent 读完全部页、不修改审批或执行授权。

## 分页边界与配置

源端一页的结果保存在 MCP Pod 临时 SQLite 快照中；续读该快照不重新查询 Kubernetes。读取完快照后才交付源端下一页游标。请求参数须保持一致，仅替换 continue_token。

- `AIOPS_RECORD_CURSOR_DB`：默认 `/tmp/aiops-record-pages/snapshots.sqlite3`。
- `AIOPS_RECORD_CURSOR_TTL_SECONDS`：默认 600 秒。
- `AIOPS_RECORD_CURSOR_CACHE_BYTES`：默认 33554432 字节。
- 每次返回仍限制为 12000 字节；单条记录超限明确报错，不静默截断字段。
- 过期、淘汰或 Pod 重启导致游标失效时，明确要求重新查询，不拼接不同快照。
- 当前 MCP 单副本；扩展多副本前需共享存储或会话亲和设计。
- 分页仅保证可续读，Agent 未读取后续页时仍只能报告部分覆盖。

3. 前端：101 项测试通过，lint、类型检查和构建通过；仍有既有 bundle 大小警告。
4. 线上真实 MCP 只读调用：原失败的 9 字段、page_size=100 查询返回全部 72 个 Pod，共 5 页（11549、11411、11373、11548、6416 字节），同一快照、无重复、无缺失；每页通过部署版后端解析器。不同 SSE 会话续读通过，总耗时约 0.41 秒，不包含 LLM 推理。
5. 线上 Pod ready 分组成功：68 个 true、4 个 false；这是就绪分布，不等同于完整故障诊断。
