# 通用修复执行（11.0.198）

当前 remediation 路由与深度总结共享 POD_REMEDIATION_PROMPT。
Agent 决定取证、资源、操作、参数、顺序和验证方式，输出 RepairDraft。
执行器按 review/auto 配置执行命令，不根据故障或资源类型插入检测、重启、字段补丁或恢复判断。

- 默认操作白名单/黑名单为空；显式管理员配置仍生效。
- 每个动作保留原样命令审阅、会话归属、取消、超时和实际执行结果。
- dry_run_command、verify_command 可选，非空时同样属于待审阅动作。
- 不再自动读取 Pod、遍历 ownerReferences 或核验 generation。身份检查由 Agent 按需要选择。
- 传输是单条 kubectl argv，不是本地主机 shell；连接身份不能被命令覆盖。
- 没有资源级或 namespace 级沙箱；宽 RBAC 意味着批准错误命令也可能影响其他资源，需审阅命令及其引用清单。
- 命令成功仅报告 needs_followup，不自动认定故障消除。

这仍是 Agent 规划 → 审阅 → 顺序执行的架构，不是执行失败后自动重新规划的闭环；失败停止并反馈，可继续会话处理。
历史兼容执行器仍在 app/core/remediation/agent.py、executor.py，保留旧逻辑；本轮不将它们接入当前默认 pod 执行路径。
