# RCA 完整报告恢复与展示验证

## 问题与范围

真实运行 `b866910ed1ba4752` 并未丢失四组正文，但前端默认全部折叠；RCA 只被要求生成“正式报告”，没有完整继承旧报告的现象/证据表/因果分析结构。g3 正文存在双重转义的段落换行。g4 的模型服务 500 `utls: TLS handshake: EOF` 未被识别为致命连接错误，继续生成了部分报告。

本轮不改变异常选择、工具调用自主性、分组策略、保护区、汇总预算或修复审批；不新增全文二次总结调用。真实测试另发现 Pod Kind 大小写影响既有分组，增加契约入口兼容修正。

## 实现

1. RCA 直接生成供用户阅读的完整报告，包含诊断结论、异常现象、关键证据、原因分析、待核实与采集边界。
2. 关键证据表要求真实工具结果、时间/来源、数值/单位/错误原文及诊断作用；未采集、失败、空结果明确区分。禁止为了丰富报告补造数据或强制追加查询。敏感配置只展示键名或脱敏片段。
3. summary 只用于导航/总览；完整报告仍由代码逐组拼接。conclusion 不接收全文或工具历史，不重新分析各组根因。
4. 前端报告卡片默认展开，展开时隐藏重复的短摘要；用户可自行折叠。仍每次展示 10 组，并保留完整报告复制/历史恢复。
5. 通用格式处理只恢复正文中的双重转义段落分隔，不使用 unicode_escape，不解码代码块/行内代码，也不改变路径或单个反斜杠 n。
6. OpenAI SDK 模型错误中的 TLS handshake EOF 进入现有致命断流路径；普通工具异常不会因此被误判。停止 RCA/汇总并提示 LLM API 服务连接中断，不将残缺草稿包装为成功报告。
7. DiagnosisEntity 在契约解析入口将 Pod/pod/POD 规范为 Pod，其他资源类型不变；不增加故障规则，不重新选择异常。混合大小写的同一对象仍按重复身份拒绝。

## 边界

报告丰富度来自实际取证，不保证每个维度都有数据，也不能保证模型每次都确认最终根因。已有历史报告会默认展开，但不会被重新生成。100 组为构造回放，不是 100 个真实故障的全链路压测。本轮专项测试通过不等于全部仓库旧实验测试均通过。

当前报告仍有较多限制说明、较长的归档路径；引用是证据定位标识，不保证浏览器可直接访问该服务器文件。报告变丰富会增加 RCA 输出 Token；本次未做同环境重复性能对照，不能声称零延迟开销。未另加一轮全文润色或模型核验调用。
