## 契约与职责

`app/core/workflow/diagnosis_contract.py` 定义 `diagnosis-handoff.v1`：

- `summary`：辅助说明，不代替对象清单。
- `targets`：稳定 target_id、通用资源身份、现象、Agent 决定的处理状态与理由。
- 每个目标保留 `facts`（关键内容、观测时间、真实来源引用）、`findings`（判断与 fact_ids）、
  `unknowns`、`next_questions`、`runbook_refs`。
- `coverage` 与 `limitations` 表示覆盖边界，不能用工具成功替代完整性。

定位自主选择目标，分组直接投影这些目标，不再调用第二个模型重新提取。
现有 Pod 并发执行器只对可调查的 Pod 分组；出现其他待调查资源类型时保留完整合同走单路，
不为了套用 Pod 工具参数丢弃或转换对象。无异常、未定位到对象、已评估、暂缓均可由 Agent 表达。

Evidence/RCA 沿用 target_id，分支只接收本组目标合同。缺项保留上一阶段内容并明确标记未完成；
重复身份、跨组对象、虚悬 fact_id 等格式/关联错误不被当成正常完成。
事实可增量输出，程序合并旧事实。相同 fact_id 的内容变化创建带 previous_fact_id 的新版本，
保留旧版并调整当前 findings 的引用；不判定两版谁更正确，不用逐字相等作为诊断成功条件。

`protected_handoff.diagnosis_handoff` 在压缩时按原结构保留。
并发汇总保存各分支最新合同；修复记录保存单路与分支合同，按组交付，不重新解析整篇报告。
原始工具正文仍归档/按需回读；不是把全部正文重复放进 facts。

无工具且 max_steps=0 的结构化节点复用单次 native structured 调用，
避免把原本工具自由的 RCA 放入零步数/零超时预算的 Agent 循环。
普通 QUERY、审批、修复命令权限不因本次改动变化。

## 边界

结构化合同保证已交接内容可追溯，不证明模型选择了所有异常或结论正确。
模型仍可能漏选目标、生成不充分事实、错误引用工具标识或误判覆盖范围；这些须评测而非故障特判。
保护内容不静默字符截断；若目标与核心事实本身超出上下文预算，运行应明确不完整，不能保证无限规模。
事实版本会增加少量体积，当前阶段数量有界；不存整份工具结果以控制增长。
来源引用目前仍可能是模型输出的工具/对象标识，不等同于全部都能自动解析为归档路径。
