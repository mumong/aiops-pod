# 常见 Pod 异常的修复分流

2026-09-20。先判断技术上是否有明确修复，再判断当前执行器是否支持；RBAC 放开不代表所有命令已对 Agent 开放。以下由模型结合 Runbook 和真实证据判断，不是固定故障代码路由。

| 场景 | 具备明确操作的条件 | 不能直接自动修复的情况 | 当前受限执行器 |
|---|---|---|---|
| c01 Pending | requests 误配置且有正常需求基线，可校正资源值 | 真实容量不足、PVC 未绑定、设备缺失、未知调度需求 | 支持有依据的 CPU/内存资源调整；其他需人工 |
| c02 ImagePull | 明确错误 tag/镜像引用，已验证正确 digest/tag | 凭据、证书、网络未知；不能猜 latest | 镜像/Secret 修改需人工 |
| c03 VolumeMount | 引用对象/键/路径写错且正确值已证实 | 数据丢失、CSI/主机目录/存储权限问题 | 卷引用与存储操作需人工 |
| c04 ConfigError | ConfigMap/Secret 键或引用错误，有准确配置 | 缺少未知业务值、证书、密码 | 配置修正需人工 |
| c05 Sandbox | NAD 引用错误，明确正确网络，或确认不再需要附加网络 | CNI/IPAM/runtime 故障；未知 NAD 配置 | 注解/NAD 修改需人工，不猜网络参数 |
| c06 CrashLoop | command/env 等错误，有已验证正确配置；或外部故障已消除但应用需要一次重启 | 代码崩溃、反复 OOM、依赖原因未解决 | 仅在外部原因已解决时支持一次滚动重启；配置修正需人工 |
| c07 应用 HTTP 500 | 已知配置错误且有正确值 | 未知依赖或应用逻辑缺陷 | 配置/代码修复需人工 |
| c08 OOM | 有界负载，确认为 limit 配置不足且目标值有依据 | 无限增长/泄漏、节点 OOM、缺少可靠基线 | 支持有依据的资源修正；无限增长默认不反复扩容 |
| c09/c10 探针失败 | 正确监听路径/端口/启动耗时已知，可修正错误探针 | 应用真实 503、依赖故障，不能删除探针掩盖错误 | probe/env 修改需人工 |
| c11 Terminating | 外部清理完成、finalizer 确认残留 | 存储未释放、节点失联、grace 未到期、清理状态未知 | 不开放强删/finalizer 删除 |
| Evicted / NodeLost | 先查健康替代实例与节点压力，避免重复处理 | 平台容量、节点或数据一致性问题 | 不开放节点/存储破坏性操作 |

当前三个常驻故障：case-05 需要有效网络配置或业务确认取消附加网络；case-09 需要核实并恢复正确应用配置；case-08 代码持续分配内存，增大限制只延迟复发。不存在“一条安全通用命令根治全部”的结论。

## 生成动作所需依据

Runbook 为每类故障补充了“可执行修复决策”：现象/原因、正确值来源、真实 Pod→控制器身份、验证和回退条件。手册中的参数模板不能原样执行。条件不足、不在命令白名单或需要外部操作时，说明具体原因与人工方案，不继续循环找同义命令。

稳定有界负载的资源不足可以修正；无限增长只在用户明确请求临时缓解时提供扩容，并标明会复发。rollout 成功只证明部署完成；恢复需观察覆盖历史故障周期的状态和业务检查。

## 权限与前端

按管理员明确要求，AIOps 与 MCP 的既有 ClusterRole 增加所有资源/API group/verb 及非资源 URL 权限；这是集群管理级凭据风险。Agent 只读工具集、写命令策略、人工批准仍独立生效。收紧权限可删除两份 deploy/rbac.yaml 的通配规则后重新 apply。

审批界面区分对象、风险、预演/执行/验证命令；原始 JSON 折叠，单独展示倒计时。执行前立即推送阶段状态，执行结果替换同组同动作同阶段，避免审批后空白等待。点击“生成修复方案并审阅”只启动规划，不批准执行。
