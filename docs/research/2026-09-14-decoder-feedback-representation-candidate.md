# 候选：基于字段回读偏差的观测表示局部展开

日期：2026-09-14。状态：扩展方案草案与近邻筛查，未实现模型实验，未建立新颖性结论。不是现有功能说明，不是专利查新完成报告。

## 1. 选择这个问题的理由

前序研究分别考察了有限输入中的记录选择、去重、联合字段、反例恢复。普通无损共享和固定保留反例往往已经能解决所展示的问题。继续增加智能体或细化规则，没有形成足够明确的新增必要性。

本候选暂时固定被展示的记录集合，只研究它的表示方式：**相同字段均已进入模型输入，程序也能精确解码，但模型可能不能正确恢复字段的所属对象或角色。** 此时增加检索记录不能直接纠正解读方式，完全展开又可能超过预算。

这是一项有一般意义的模型输入工程问题，不限定 OOM 或某一个 Pod。运维中的对象 ID、Requests/Limits、计量单位和时间窗口提供具体实施数据。该问题在本项目模型上的发生率尚未测量，不能将论文或外部基准的结果当作本项目故障记录。

## 2. 第一性原理和借鉴对象

普通编码的正确性要求 `decode(encode(D)) == D`。模型直接阅读压缩文本时，并不实际调用这个确定性 decoder；前述等式不能保证模型回读结果也相等。

从通信中的反馈重传借鉴一个有限思想：接收端发生可观察读取错误后，发送端增加针对性的显式信息。此处不处理信道比特错误，也没有语义 CRC；核对的是程序已知的具体字段值。模型答对几个字段不是对整个输入的“接收成功确认”。

从可逆数据变换借鉴来源映射：编码时记录每个源字段采用了哪段共享头、字典项或逐行值。读错哪个字段，就能够定位涉及的表示结构；无需模型凭空定义字段之间的关系。

以上原理不是新发明。拟研究的区别是：**字段回读偏差通过编码来源映射控制局部展开，而不是只更换整份提示词、追加取证或改写诊断。**

## 3. 最小例子：先说明所有判断依据来自哪里

源记录是程序保留的结构化观测，角色已经由源 schema 或明确解析路径提供：

```json
[
  {"id":"m1","uid":"pod-a","role":"requests","unit":"byte","value":134217728},
  {"id":"m2","uid":"pod-a","role":"limits","unit":"byte","value":268435456}
]
```

说明性共享表示：

```json
{
  "common":{"uid":"pod-a","unit":"byte"},
  "groups":{"g1":{"role":"requests"},"g2":{"role":"limits"}},
  "rows":[
    {"id":"m1","group":"g1","value":134217728},
    {"id":"m2","group":"g2","value":268435456}
  ]
}
```

这个两行例子只用于解释机制，不声称共享格式更短；小数据应直接保留原文。此前 20 行标签共享的字节节省也不代表本例 token 节省。

程序生成回读任务 `{"id":"m2","field":"role"}`，正确答案由源记录直接取得，为 `limits`。假设模型返回 `requests`：这是一次人为设定的错误示例，不是真实模型输出。

编码器已有映射 `m2.role -> rows[m2].group -> groups[g2].role`。程序据此可以把 g2 成员的 role 明写到行内。它不修改源值，也不把 Requests 和 Limits 的关系交给另一个模型确认。

## 4. 完整候选流程

1. **固定源记录与表示范围。** 保存版本、对象、窗口和记录 ID。当前轮保持相同记录集合，以免把内容选择效果混同于格式效果。超出整个实验范围的遗漏另行披露。
2. **生成有限种可逆表示。** 例如完整 JSON、共享公共字段、带表头的逐行表示。编码器同时产生“源字段位置 → 表示依赖路径”的映射；先通过确定性解码检查。不能证明可逆的转换不进入本候选。
3. **生成可判分的读取任务。** 从源记录生成指定 ID、指定字段的取值问题，必要时包含多个同名字段角色。任务限于字段读取，不把“是否 OOM”一类根因问题当作已知答案。输入携带精确表示版本，预期答案仅在程序侧。
4. **由实际消费模型回读，程序比较。** 使用后续消费该格式的模型与配置，记录返回值、缺失、格式不合规。不能用另一小模型通过测试来认证目标模型会读对。辅助小模型可以推荐检查位置，但不能取代源值核对。
5. **做有限对照，不武断归因。** 对失败字段提供完整字段表示进行对照读取；完整形式也失败时，记为当前回读任务未通过，不继续假定展开可修复。压缩形式失败、完整形式成功也只是经验线索，受采样随机性和上下文差别影响。
6. **沿依赖映射局部展开。** 根据失败字段位置，把相应共享字段复制回相关行、或把多级字典引用改为完整字段路径。保留未涉及结构，重新解码验证、估算目标 tokenizer 下的总长度，并进行有限复测。展开不改变源事实或从未展示集合补造记录。这里以减少间接引用为明确操作，不声称已识别模型内部错误机制。
7. **有界结束。** 配置最大检查数、展开轮次、耗时及总 token 成本；达到上限则回退可容纳的完整格式，或缩小记录范围并披露遗漏，或标记读取未确认。后续输入仍核对版本和已测表示，不能以旧版本回读结果认证新的布局。

验证通过的含义仅为“这些字段在这些回读调用中被读对”。不保证未测字段、新的上下文、另一个模型或后续诊断都正确。若把读取与诊断分为不同调用，后者是否受益必须单独实验。

## 5. 为什么不能忽略简单替代方法

至少比较以下基线，否则候选可能只是在修复自己制造的间接格式：

| 基线 | 必须回答的问题 |
|---|---|
| 直接完整 JSON | 是否本来就能装下？若能，额外检查是否值得？ |
| 固定成熟紧凑格式 | TOON、表格或字段共享是否已足够？ |
| 模型只输出字段 ID，程序代取值 | 若最终报告值可全部由程序渲染，何必让模型回读全部数值？ |
| 失败后直接纠正该字段 | 是否比展开整类共享结构更便宜、同样有效？ |
| 一次离线选择全局格式 | 是否无需每次诊断额外测试？ |

可能适用的条件是：后续推理确实需要模型区分多个字段角色，存在多个相同表示结构的后续读取任务，且整份展开明显更昂贵。它只是适用假设，尚无实验支持。若只需显示一个数值，程序代取或直接纠正通常是更强的基线。

## 6. 已取得的近邻证据及边界

### 6.1 TOON：紧凑表示与模型读取准确率已有直接实践

固定仓库提交 `f151a5d830d001bc244395b891183cba37e0d935`，GitHub API 返回提交日期 2026-09-03，早于研究日期。

核读该版本 [packages/toon/README.md](https://github.com/toon-format/toon/blob/f151a5d830d001bc244395b891183cba37e0d935/packages/toon/README.md) 的概述、格式示例、适用/不适用条件和读取准确率基准部分。

其说明明确把 JSON 数据编码为模型输入用的无损表示，均匀记录共享表头，并用 244 个数据读取问题、4 个模型比较格式。数据包含事件日志、嵌套配置、字段缺失和行数异常。基准是项目方报告，不是本轮复现；不引用其整体百分比作为本项目收益。

因此，“对模型使用紧凑可逆格式”“用已知答案的数据读取题评价格式”都不能作为未有人提出的主张。候选的待查差别仅剩实例级错误反馈是否通过源字段映射控制局部展开。

### 6.2 FormatSpread：格式选择不是天然无关变量

OpenAlex 元数据及摘要索引确认：*Quantifying Language Models' Sensitivity to Spurious Features in Prompt Design or: How I learned to start worrying about prompt formatting*，arXiv:2310.11324，2023-10-17。

本轮只读取数据库所收摘要，未获得并精读论文全文。摘要报告保持含义的格式变化影响性能，提出 FormatSpread 评估多个格式的性能范围；还指出模型之间格式表现相关性较弱。因此不能借另一个小模型的格式偏好直接认证消费模型。

### 6.3 通信反馈迁移也不是空白

Crossref 与 OpenAlex 核实 *Adaptive Bit Rate Control in Semantic Communication With Incremental Knowledge-Based HARQ*，DOI `10.1109/OJCOMS.2022.3189023`，2022。本轮只核实元数据，未读取全文；不依据标题推断其是否涵盖本候选。

它是下一轮需精读的跨域近邻，而不是已经证明我们的方案新颖的佐证。不能只把通信里的反馈和冗余换成模型里的回读与展开就宣布创造性。

### 6.4 专利检索现状

本轮尝试 FPO 的 language model/serialization 查询、Google Patents 查询与通用搜索，分别遇到 TLS 连接重置或超时，没有取得新专利检索结果。此前已核读的 US9218354B2（查询感知压缩/解码）、US20250173314A1（模型与可检查反例反馈）仍是组合分析背景，但不能推定它们完整涵盖当前新提出的局部表示处理。

因此本轮没有资格作“未检出相关专利”或“新颖性通过”结论。精确待查关系为：读取测试 → 源字段与编码依赖定位 → 选择性显式化 → 同一数据的有限预算再输入。

## 7. 最小验证计划与当前结论

先做离线实验，不连接正在运行的 Agent：固定源集合、目标模型、任务集和 tokenizer；比较完整 JSON、固定共享格式、直接纠正、全局格式选择与局部展开。将用于触发展开的读取题和后续评估题分开，计入检查调用全部成本。至少记录字段 ID/角色/值准确率、未知率、总 tokens、耗时和后续推理效果。

首个否定条件：局部展开仅让已经给过答案的题变正确，对未用于修复的同结构字段无帮助。第二个否定条件：总成本高于直接完整输入且无准确率优势。第三个否定条件：程序代取值就能完成下游任务。不能只报告有利样本。

**当前选择：保留此项作新候选草案，不立即推荐申请。** 它相较前序方案改变了具体操作对象：不再继续挑选或补读观测，而是处理模型对已入上下文数据的解读偏差。可执行步骤与正确答案来源已经明确，但实际收益、局部处理的必要性和专利区别均未验证。研究总目标继续保留，不能凭这份草案宣称完成。

## 8. 隔离原型：程序部分可实施，但首次反馈成本更高

新增 [representation_feedback_feasibility.py](representation_feedback_feasibility.py)，使用构造记录和人为注入的回读答复。没有执行真实模型，没有调用业务模块或网络。

原型共享 uid、role、unit 等明确字段，编码时按这些字段的实际值形成共享组；模型答复给出具体记录 ID 和字段名。程序先比较源字段，再沿该记录的组指针找到共享字段，把该字段展开到同组各成员。只处理这一种表示，不假称已经实现任意 schema、格式自动学习或多层依赖优化。

10 项检查通过：

- 完整编码解码逐记录一致；局部展开不改变源值、顺序或记录范围。
- 只展开被指向组的对应字段，其他组仍保留共享表示。
- 字段缺失与 null 区分；重复 ID、未知 ID、旧表示版本被拒绝。
- 超过预算时不提交半成品；已是显式字段仍读错时返回未解决，不无休止展开。
- 正确答复不触发变更；载荷与保留源摘要不一致时拒绝解码。

摘要/hash 检查是本地一致性检查，不是抵抗恶意重签名或重算 hash 的真实性认证。版本检查也不能证明真实模型已理解该版本。

### 8.1 同一组 100 条合成记录的表示成本

统一采用紧凑 JSON、UTF-8 字节数：

| 表示/发送方式 | 字节数 |
|---|---:|
| 完整源记录列表 | 8,601 |
| 初始共享表示（含源摘要及分组元数据） | 5,219 |
| 仅将 limits 组的 role 展开到 50 个成员 | 6,003 |
| 首次共享输入＋一次展开后重测，两份完整载荷累计 | 11,222 |

局部展开后的单份表示仍小于原文，但首次反馈的两份载荷合计已经大于直接原文，尚未计入读取问题、模型答案、完整形式对照和最终诊断输入。不能把 6,003 小于 8,601 当成总成本降低。

另一方面，**累计通信成本与单次上下文容量不是同一约束**：若原文本来放不进一次输入，多轮较短输入仍可能有意义。这里没有实际 tokenizer，以上字节数据不能推导模型的真实上下文可容纳性、缓存费用或推理耗时。

### 8.2 对选择的影响

保留“本地程序可以准确控制局部展开”的结论，不升级为“模型能因此读对”。目前最需要验证的是：相比直接纠正一项读取答案，展开同组字段能否改善未用于修复的后续读取/推理；以及收益能否覆盖额外调用。

真实模型测试需要独立测试接口及明确调用许可。本轮已发出非阻塞询问，未探查凭据、未调用线上工作流，也未把等待答复作为全部研究无法继续的理由。

## 10. 跨领域实质对照：语义错误检测已控制再传输

### 10.1 新核读的公开实现，不混同于上一节的 2022 论文

研究：*Topology Data Analysis-based Error Detection for Semantic Image Transmission with Incremental Knowledge-based HARQ*，arXiv:2403.11542。OpenAlex 核实发布日期 2024-03-18 并提供摘要索引；[仓库 README](https://github.com/nf129/SC-TDA-HARQ/blob/39139dd794a45bf6f94ac3dfba765e44318367d8/README.md) 明确将此论文列为实现对象。

固定提交：`39139dd794a45bf6f94ac3dfba765e44318367d8`，GitHub API 返回提交日期 2024-11-06。核读 README 和 [network.py](https://github.com/nf129/SC-TDA-HARQ/blob/39139dd794a45bf6f94ac3dfba765e44318367d8/network.py) 全部内容；未运行训练或推理，未下载预训练权重，未取得论文全文。其他编码器/TDA 模块尚未逐层核查。

摘要明确指出：位级 CRC 不足以处理图像语义歧义，使用基于拓扑数据分析的错误检测来决定是否重传，并结合之前传输的信息。

`network.py` 的可观察实现为：

1. 编码图像得到 feature。
2. 开启信道时对 feature 调用两次信道函数，得到两个 noisy_feature。
3. 首次把第一份特征与零张量拼接，交给 decoder 得到重建图像和辅助输出。
4. 调用 `encoder_sim28` 得到 corr，进行维度均值归约。
5. 若 corr 小于 0.5，则改为拼接两份接收特征，再执行 decoder。

必须忠实限定：在这个 forward 实现里，第二份 noisy_feature 预先已经计算，条件分支决定其是否用于第二次解码；不能将其直接当作真实网络的按需发包时序或完整传输计费。函数中 CBR 按基础 feature 大小计算，本轮不据此推出含重传的端到端带宽。这里只确认存在检测结果控制再次组合/解码的程序关系。

### 10.2 与当前候选的精确比较

| 比较关系 | 该公开实现/摘要 | 当前候选草案 |
|---|---|---|
| 已交付的对象 | 经信道后的图像特征 | 无损编码的结构化工具观测 |
| 可用反馈 | 网络输出并归约的 corr | 指定 ID/字段的模型回读值与源值比较 |
| 后续改变 | 合并第二份接收特征并再次解码 | 按编码依赖路径将共享字段显式写入相关行 |
| 可直接判定的范围 | 源码只显示阈值分支，不等于语义绝对正确 | 特定字段回答是否相等，不等于整个诊断正确 |
| 尚未证明 | 本轮未复现论文效果 | 未运行真实模型，未证明局部展开优于直接纠正 |

由此不能再把“位级/程序解码正确不等于语义理解正确 → 检测理解质量 → 增加信息再次处理”这一抽象链条当成全新的跨域思想。当前候选可以描述具体差别，但有差别仍不等于非显而易见。

### 10.3 一个必须修正的技术表述

**错误字段定位不等于错误原因定位。** 例如 m2.role 返回错误，程序能确定需核对的源字段和可修改的表示位置，却不能据此确定模型究竟混淆了行、共享组、字段角色还是任务指令。局部展开是明确可执行的处理策略，不是由错误唯一推导出的正确修复。

因此交底书不能写“通过依赖映射准确定位模型理解错误原因，并保证修复”。应写成“依据回读偏差确定候选展开位置，执行表示调整并重新评估；不通过则终止或回退”。若未来实验发现只有少数已测字段有效，需要如实限制效果范围。

### 10.4 专利搜索渠道与证据质量记录

## 11. 更直接的模型压缩近邻：Nano-Capsulator

来源：Yu-Neng Chuang 等，*Learning to Compress Prompt in Natural Language Formats*，NAACL 2024，7756–7767，DOI `10.18653/v1/2024.naacl-long.429`。

- [ACL 正式条目](https://aclanthology.org/2024.naacl-long.429/)
- [正式 PDF](https://aclanthology.org/2024.naacl-long.429.pdf)
- 本轮核读摘要、PDF 第 3–5 页，含 §3.1–3.2、Algorithm 1、Figure 2 及实验设置开头；没有声称核验全部附录或复现效果。
- PDF SHA256：`8279dac3deaee520b85d34de82edfddc54d4a622ca7e6d45e69b52582c70def7`。

### 11.1 对方确切做了什么

1. 压缩模型把长提示 K 转成自然语言 Capsule Prompt C。
2. 通过原文与压缩文本的隐藏表示距离构造语义保持损失。
3. 抽取下游任务问题，分别将原提示与受长度截断的压缩提示交给冻结下游模型，计算奖励。
4. 将奖励与语义损失结合优化压缩模型；推理时由训练后的模型生成压缩文本。

论文具体实现以隐藏表示 MSE 计算奖励，并说明可替换为准确率、GPT4Eval 等。不能只把 Figure 2 的答案示意图描述为完整实现始终用字符串精确比对。主实验使用 Vicuna-7B、LoRA 和两张 A40；这些是论文实验设置，不是本轮所运行配置。

这项工作已经把“目标模型的任务反馈—压缩效果—长度限制”形成闭环，因此上位的“模型反馈驱动压缩”不能独立成为当前候选的新点。

### 11.2 当前候选还能主张哪些具体差别

| 项目 | Nano-Capsulator 所核读方法 | 当前草案 |
|---|---|---|
| 改变对象 | 训练压缩模型的参数，生成自然语言短提示 | 既有确定性编码结构中的共享字段位置 |
| 主要核对依据 | 长/短提示的表示或下游输出比较；文中也允许其他奖励 | 已固定的源记录字段真值 |
| 调整粒度 | 生成的 Capsule Prompt；不是本文已核读部分中的源字段定向展开 | 沿记录 ID 与编码依赖路径展开相关组的特定字段 |

### 11.3 当前可供交底讨论的方法骨架

只保留实际相互影响的步骤：

> 对结构化工具观测生成可逆的共享表示及字段依赖映射；以源记录生成字段读取核对项，将所述共享表示提供给消费模型；根据模型读取结果与源字段之间的偏差，沿所述依赖映射确定局部展开位置；在源记录保持一致及表示预算约束下调整所述共享表示，并对调整结果进行有界复核或回退。

当前还不宜加入“自动判断所有关键字段”“定位模型内部错误原因”“保证诊断正确”“总 token 必然降低”等没有证据的效果。也不应把目标变成必须额外训练一个小模型；当前草案的可执行部分没有这项需求。

### 11.4 后续决策所缺的证据，不继续以原型测试替代

程序转换测试已经足以说明基础步骤能实现。继续增加同类往返测试，不能回答剩余的核心问题：

1. 目标模型对同一组数据是否确实存在可复现的表示相关误读，局部展开是否改善未参与修复的字段/任务。

### 14.1 Oracle 并非只能做整体提示优化

### 14.2 必须区分专利方案合理性与产品收益验证

用户明确允许未实现的扩展，也没有要求先证明产品效果优秀。前序记录把真实模型实验列为继续推进的必需条件，容易给人错误印象。修正口径如下：

1. **模型实验不是提出候选方法的先决条件。** 当前程序原型足以说明源字段定位、局部展开、版本与预算检查能够执行；模型误读后展开显式字段具有可解释的作用路径，可以作为待验证技术假设讨论。
2. **没有模型实验，就不能宣称实际改善读取或根因准确率。** 这是限制效果措辞，不是禁止继续设计或做专利对照。
3. **成本更高也不自动否定方案。** 单次容量、总成本、读取可靠性存在不同目标；应如实保留权衡，而不是要求所有指标同时超过现有方法才允许形成候选。
4. **但新颖性/创造性不能由可实现性替代。** 目前最薄弱的仍是：剩余局部展开控制关系是否具有足够区别贡献，而非再增加十个程序单元测试。

### 14.3 当前可辩护与不可辩护的主张

可辩护：编码器已经知道共享关系，因此程序可以确定性地调整特定共享字段的显式位置；这使修复动作不必依赖另一个模型自由改写事实；原型验证所测调整保持原记录一致。

尚不可辩护：根据回读错误唯一识别模型内部原因；错误组展开必然改善所有同组字段；该映射与展开控制具有足够创造性；该机制已经优于精确字段纠正或静态带完整字段名的模板。

研究选择继续保持具体：可以把“受源映射约束的表示调整”作为候选讨论，不能把“模型反馈＋字段级精炼＋预算”重新当作贡献。也不再以缺少模型接口作为概念研究的全面阻塞理由。

## 15. 回到现有工程后的优先级调整

本轮只读核对现有三维观测输入后确认：本原型使用的 groups/rows 共享字典是研究构造，不是 `observability_projection.py` 当前的指标记录格式。当前 metric、value、unit 等主要逐条保留，部分身份字段采用顶层对象信息。不能把“字典编码后误读”当作已经查明的项目故障原因。

真实投影函数的构造输入执行另外暴露了“有效空 ledger 退回旧格式 facts，再在摘要中省略逐条 UID”的边界，详见 [权威空结果研究](2026-09-14-authoritative-empty-projection-study.md)。该观察不是线上事故复现，也没有把 `related_context` 变成 `direct`；它表明至少一类输入问题可在消费模型之前发生。

因此当前候选优先级降低，不继续为其新增读取模型或重复相同原型测试。这个调整并不证明局部展开不可能有益；它表示尚无足够项目证据和区别贡献让它优先于更直接的输入资格问题。

另核读 [US12524625B2，Prompt refinement service for enhancing generative model output](https://www.freepatentsonline.com/12524625.html) 的 FPO 首页信息和全部权利要求 1–20：按输入相似性选择 prompt refiners 并合并输入；从属项包括负反馈更新、评分库及分层决策树选择。它是输入增强策略选择的背景，不应仅据标题将其当成源字段定位展开的直接公开。本轮未精读说明书或核对官方扫描件。
