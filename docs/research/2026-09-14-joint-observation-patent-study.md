### 1.2 为什么仍可研究扩展

现有“完整代表记录 + 省略其他记录”本来就是合理基线，具有源字段不跨行混合的优点。本文只考虑另一种需求：数据量很大，希望在有限输入内展示比少量整行更多的联合分布或观测结构，不能退化成互不关联的单列统计。

如果整行代表已经足够，或者工具只返回少量记录，**无需采用本方案**。不能人为制造一个较差摘要，再声称修复它证明优于当前系统。

D 指一份版本固定、确实已取得的结构化观测集合，不等于源系统全部历史。原始工具只返回聚合结果、没有底层记录时，不得补造底层行或将聚合值视为同一事件字段。

## 2. 第一性原理：压缩丢掉的是哪部分信息

两个不同源集合：

| 集合 | 第一条 | 第二条 |
|---|---|---|
| D1 | 状态 200，耗时 2,000 ms | 状态 503，耗时 20 ms |
| D2 | 状态 200，耗时 20 ms | 状态 503，耗时 2,000 ms |

独立保存“状态集合 {200,503}、耗时集合 {20,2000}”得到相同 S，却不能回答“失败请求是否达到 2,000 ms”。这是信息不足，不是通过更强推理必然能够补回的内容。

数学上，将观测视为关系 D，字段子集为 F。`πF(D)` 是这些字段在同一源记录中实际出现的取值组合。仅保留各个单字段投影，其笛卡尔积一般比 D 大，包含源集合没有支持的重组。

本文只对有限记录的等值字段关系作确定性处理，不推断因果、故障类别或任意自然语言陈述。源集合未出现不等于现实中不可能发生。

## 3. 跨领域迁移：借什么，不能声称什么

### 3.1 数据库关系投影与无损连接

数据库早已区分同一行联合值与各列独立取值。PostgreSQL 官方说明 CROSS JOIN 会产生所有行组合，而带条件的 JOIN 由连接条件限制匹配。

来源：https://www.postgresql.org/docs/current/queries-table-expressions.html （本轮/前轮读取相关连接定义）。

迁移：将摘要表示为若干明确有源支持的联合字段块，而非让自然语言自行补齐关系。不能把关系投影、连接依赖或保留主键当作新发明。

### 3.2 数据分析中的“聚合值 + 来源行”

Pandas `groupby().first()` 默认按列取首个非空值，可能来自不同行；`nth(0)` 取一整行。DuckDB `arg_max(arg,val)` 从最大 val 所在行取得 arg，表明绑定极值与该行属性已有直接方法。

- https://pandas.pydata.org/pandas-docs/version/2.2.3/reference/api/pandas.core.groupby.DataFrameGroupBy.first.html
- https://pandas.pydata.org/pandas-docs/version/2.2.3/reference/api/pandas.core.groupby.DataFrameGroupBy.nth.html
- https://duckdb.org/docs/current/sql/functions/aggregates.html

迁移：归档侧保存联合取值到源记录的见证索引。不能把 arg_max 行绑定或 fact ID 单独作为新点；并列极值、NULL 也要有明确策略。

### 3.3 软件变异测试与测试选择

借鉴的是“主动构造小变化，检查一个表示是否能暴露变化”，不是等模型实际犯错才寻找遗漏。字段重组相当于对照变化；联合字段块相当于能够区分部分对照的检查条件；预算内选择具有成本的检查条件。

测试最小化、选择和优先级本来就是成熟领域。Yoo、Harman 的综述 DOI `10.1002/stvr.430`，本轮通过 Crossref 核对题名、作者、2012 年出版信息及摘要；没有假称读完全文。

专利搜索也找到变异测试近邻，如 US11307962B2、US11119902B2。此轮仅看检索摘要，不能据此做权利要求结论。测试覆盖/集合覆盖/贪心选择都不是本文独有。

迁移中的关键限制：重组记录只用于程序侧分析，不作为真实观测发送给诊断模型；“没区分某个重组”只是表示层的不足，不等于模型已经产生幻觉。

### 3.4 模型的合适职责

模型可从有限候选中判断当前问题更关注路径、响应、耗时还是时段。源记录是否存在、预算是否满足、字段值怎样取得，交给程序。

这不同于让小模型凭空学习一种全局“真实关系规律”。不能根据当前快照没有某组合，就训练它断言现实世界中该组合永远错误。

### 3.5 新增强近邻：FASTDC 的证据集合与最小覆盖

Chu、Ilyas、Papotti，*Discovering Denial Constraints*，PVLDB 6(13)，2013。DOI：`10.14778/2536258.2536262`。

原文：https://www.vldb.org/pvldb/vol6/p1498-papotti.pdf 。本轮取得 12 页 PDF，核读摘要、引言和第 5—9 页相关算法段落（期刊页 1502—1506）。

文中从 schema 构建谓词空间，从真实元组对计算满足的谓词证据集合，把最小 denial constraint 发现归结为最小覆盖搜索。Algorithm 4 根据尚未覆盖证据集动态排序候选，含冗余/蕴含剪枝；还讨论近似约束和排序。

这与原型不是同一个算法：FASTDC 的对象是实际元组对及谓词约束；原型的对象是源集合未支持重组及联合投影，且增加序列化预算。但“自动构造可检查证据 → 选择能覆盖证据的条件 → 按残余覆盖动态排序”已有明确的旧技术基础。不能因为原型使用字段组而不是谓词，就自动认为该处理骨架有创造性。

## 5. 完整候选步骤：不是交给程序“理解关系”

工作名称：**基于源记录错配探测的工具观测联合字段预算投影方法**。

### S1. 固定处理域

输入 D、字段 schema、当前任务 Q、预算 B。记录来源工具、对象身份、采集窗口、解析版本和归档快照版本。不同来源或不同类型的记录分别处理；不能仅因同一 Pod 就把日志与指标当成同一事件。

每个字段保留 JSON 路径、类型、单位（有则保留）、缺失状态和源记录位置。唯一 ID 等来源元数据用于定位，不参与“区分力”评分，避免把保存 ID 当成保存业务关联。

### S2. 判断是否有采用必要

先计算原有整记录表示的实际成本。能够满足预算且符合展示目标时保留该路径；不为本方案故意制造列式摘要。高基数、缺失严重、只有源端统计无原始行时，也允许采用整记录、有限代表或明确未知。

需要更大范围联合覆盖而整记录放不下时，才评估联合投影。收益不是源集合中各条请求的因果价值，也不是保证摘要更短。

### S3. 形成候选与有限重组对照

程序建立各字段已观测取值域和同一记录的联合取值索引。在同字段内取值重组；如果重组真实存在于 D，不能作为未支持对照。只把当前 D 不存在的重组放入程序侧探测集合 Z。

小集合可以穷举；大集合采用固定随机种子、有上限的同字段交换，仅检查采样 Z。禁止把“采样未发现”报告成“所有组合都已保真”。原型只实现有上限穷举，不假称已经完成大规模采样优化。

枚举宽度有限的字段子集 F（例如先二字段，必要时三字段），得到精确投影 `πF(D)`。如果投影自身太大，就跳过、细化处理域，或保留未知；不能截掉部分投影后仍将其视为完整支持集。

### S4. 可选小模型只提供选择偏好

输入：当前任务文本、最多若干候选编号、字段名、类型、少量源示例、实际成本与可区分对照数。输出只允许候选编号及排序，不允许新的字段值或新的规则。

示例输出：`{"ranked_candidate_ids":["path+code","code+ms"]}`。

程序过滤未知/重复 ID，执行超时及长度限制。排序可以作为同等程序收益下的优先级，或在明确加权公式中提供有界权重。原型只实现同收益/成本下的排序接口及无效 ID 过滤，未调用真实小模型；没有验证模型选择质量。诊断 Agent 沿用原系统，不额外增加规划 Agent。

如果未来需要训练排序器，训练标签应来自人工偏好或明确任务评估，不能把所有未观测组合都标为现实假事实。无需把训练模型作为当前方法成立的前提。

### S5. 按尚未区分的对照分配预算

对候选 F，检查哪些 `z∈Z` 满足 `πF(z)∉πF(D)`。这些重组在加入该联合块后可以被区别出来。

每次选择当前新增区分数量与实际新增序列化成本之比较高、且能放入 B 的候选；更新尚未区分集合，避免重复计算收益。小模型不能越过源支持和预算检查。贪心不是全局最优保证。

候选不限于两字段：三元奇偶关系中，任意两字段投影都不能排除错误三元组合。若达到最大宽度仍无法区分，必须记录残余，不无限扩展。

### S6. 从源数据构建最终输入

只输出源投影中真实存在的联合值，并明确哪些是联合块、哪些是独立统计、检查针对什么范围。构造的错配对照不作为事实放入诊断输入。

模型侧预算应包含对象/窗口、联合块、来源入口、遗漏/未知声明和格式开销。原型使用 UTF-8 字节成本；接入实际模型时必须使用其 tokenizer 或可靠预算接口，不能把字节等同于 token。小模型调用本身的成本另计。

归档侧保存 `快照版本 + 联合块编号 + 联合取值 → 源记录位置列表`。这些索引不必全部进入模型上下文，但必须明确其外存成本。

### S7. 按同一依据回读与停止

需要某个联合取值的细节时，按该块及取值读取对应源记录，而不是从独立列自由拼接。版本不一致拒绝沿用旧索引；没有匹配只能说“该快照未匹配”。

原型验证了精确见证读取和版本拒绝，未实现带分页的服务接口。实际接入需限定回读条数/预算，返回剩余游标，并重新组装最终输入；不能承诺归档读取成功就代表模型已看到全部内容。

终止条件包括：预算不足、候选耗尽、对照采样上限、最大字段宽度、来源缺失、归档不可读及版本变化。输出相应状态，不认证任意自然语言根因。

## 6. 为何可能有效，以及严格不能保证什么

对每个完整、精确的投影块，源记录一定满足它；某个重组不满足任一选中块，就能在该表示的明确语义下排除它。增加这样的块不会排除 D 中真实存在的取值组合。这是集合运算性质，不需要模型理解。

但模型可能忽略格式、把独立统计误读为联合事实。原型的“未支持组合减少”是表示层指标，**不是实测幻觉率或根因准确率**。如果希望约束最终陈述，另需受限的结构化输出及成员检查；这不是当前原型已经接入的功能，也不应为了增特征扩大主方案。

不保证：恢复任意未知查询所需全部信息、推断未采集现实、证明因果、跨工具事件同一性、保留所有联合频数、模型一定正确理解或总体调用成本降低。

| 两次 raw_ref 相同 | 是 |
| structured 中的字段仍存在 | 是 |
| 第一次 context_summary 事件中仍含标记 | 是 |
| 两次都从同一未变更来源事件重新生成 | 候选相同 |

因此，这里证明的是“某个可变摘录作为下一次构建来源时会产生二次截断”，不是全局数据丢失，也不是报告一定误判。即使事实引用仍相同，当前展示的摘录也可能不同。

### 13.2 对专利立意的影响

这使“从程序来源重建”需要写得更准确：来源可能是已经裁剪过的事件摘录，并不自动等于完整原始观测。受控重建、可回读、完整含义保留是三个不同保证。

最简单的工程基线是从不可变源记录按同一选择规则重新构建，而不是从上一次摘录再次裁剪。这类似从母版重新编码以避免代际损失，不能直接宣布新颖。

一个可测的研究条件是：输入源版本、查询范围和预算不变时，重复构建不能仅因历史压缩次数而进一步失去可用内容。若预算减少、新增观测、查询变化或源版本变化，则不能要求所有历史判断永久保留；必须明确哪些变化允许选择集合改变。这个条件有助于验收工程方案，但条件本身不是完整的可申请方法。
