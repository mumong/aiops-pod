# 有限诊断输入的观测选择与补读：定向检索及跨领域构思

日期：2026-09-14。用途：专利选题与候选技术方案讨论；不是授权、侵权或完整新颖性检索结论。

## 1. 结论与检索边界

问题有工程价值，但“分组、去重、轮流选择、摘要、按需回读”不能单独作为新点。此次核验到的日志专利、网络调度、图像交互传输、LLM 上下文管理都有对应公开做法。

优先研究两个更窄的候选：

1. **基于可检查断言的反例，局部细化观测分区，而非只追加更多记录。**
2. **以最终序列化模型输入中的实际包含情况，确认补读完成，并控制其下一轮预算准入。**

二者是未完整实现的构思，不是已经发现可授权差异。第一项更适合作为进一步研究的独立问题；第二项贴近现有实现，但容易与缓存、分页、确认与事务机制组合撞车。不要为了凑特征把二者及公平调度全塞进一个主权利要求。

本轮完成：以 US10635682B2 为种子核读授权文本，并沿其引证取得 US10360184B2、US20160299934A1；重点核读首页、摘要、有关说明书段落及权利要求。另核读 RFC8290、ITU-T T.808 的有关章节、CEGAR 原论文前部，以及 MemGPT 官方介绍、LLMLingua 的 ACL 摘要、Anthropic 和 vLLM 官方技术文章。

## 3. 其他领域如何解决相似问题

### X1. 网络调度：FQ-CoDel / Deficit Round Robin

来源：RFC8290，2018-01，Experimental（不是 Internet Standards Track）。
https://www.rfc-editor.org/rfc/rfc8290.html

核读摘要及第 1—4 节相关内容。其目标包括减少突发流量的队头阻塞、隔离 DNS 等低速率流量。使用改进的 DRR 和逐队列 CoDel；按字节等成本组织服务，而非仅按包数平均。

可借鉴：把每个观测类别看作服务队列，预算按实际 token 成本记账；连续未获得展示的类别可保留调度状态，而非每轮重新从最热门类别开始。

不能直接搬的部分：网络包可以分时传输，某条诊断事实却可能需要对象、时间、单位等一起出现；它也可能超过一轮全部预算。公平不是诊断价值，CoDel 丢包策略更不能直接等价于丢证据。

结论：适合作为工程基础与强对照，不建议“轮询+欠额”单独作为主创新。

### X2. 图像交互传输：JPEG 2000 / JPIP

官方说明：https://jpeg.org/jpeg2000/
标准目录：https://www.itu.int/rec/T-REC-T.808/en
本轮核读版本：ITU-T T.808 (12/2022)，2022-12-14 批准，页面显示 2023-05-03 发布文件；不是把后来版本特征倒推给 2005 年初版。
公开 PDF：https://www.itu.int/rec/dologin_pub.asp?lang=e&id=T-REC-T.808-202212-S!!PDF-E&type=items

核读 PDF 第 13、18—19、33 页（定义、6.1、Annex B.1/B.2）。

相同问题：完整图像很大，客户端当前只需某区域、分辨率或质量层；每次重发全图浪费有限带宽。

既有机制：View-Window 指定需要的部分；data-bin 支持分段交付；服务器维护客户端缓存模型，按已有内容减少重复传输。标准明确客户端缓存有限，可能清除内容；缓存模型可依据传输确认或更新语句维护。

可借鉴：将“需要哪类观测的哪种细节”变成明确的视图需求；区分原始库、已经传回工具的内容、当前模型输入实际持有的内容。

重要反证：增量补充、记录已收到内容、缓存清除及缓存模型本身均已有。不能把“已读不等于当前持有”作为孤立的新点。需要进一步说明 LLM 的多级再压缩如何改变确认位置、补入原子单位和失败处理。

### X3. 形式化验证：Counterexample-guided Abstraction Refinement（CEGAR）

Clarke、Grumberg、Jha、Lu、Veith，经典 CAV 2000 工作。
作者公开原文：https://www.cs.cmu.edu/~emc/papers/Conference%20Papers/Counterexample-guided%20Abstraction%20Refinement.pdf

核读 PDF 第 1—3 页。为避免状态空间爆炸先建立抽象模型；抽象出现反例后，判断是否为真实反例；若属抽象引入的伪反例，则局部细分抽象状态以排除它，而不是一开始展开全部状态。原文讨论了最粗细化的困难及启发式求解。

值得迁移的是反馈控制思想：反馈不只是增加材料，也改变之前过粗的抽象方式。

边界：LLM 的自然语言摘要不是形式化模型的可靠上近似；AIOps 也没有完整系统转移模型。不能照搬 CEGAR 的正确性、完备性和收敛保证。这里只能对受支持的结构化断言、有限观测集合做明确检查。

## 4. 不能遗漏的 LLM 近邻

- **MemGPT（2023）**：官方 https://research.memgpt.ai/ 。已公开借鉴操作系统分层存储与分页管理有限上下文。核读官方摘要/介绍，未在本轮完成全文逐段分析。不能再把“外存+按需换入”作为新点。
- **LLMLingua（EMNLP 2023）**：https://aclanthology.org/2023.emnlp-main.825/ 。核读 ACL 摘要，公开粗到细压缩、预算控制和迭代 token 压缩。不是所有预算分配都未公开。
- **Anthropic Context Engineering（2025-09-29）**：https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents 。核读有限上下文、轻量引用和 just-in-time 动态加载部分。路径引用+按需读取属于公开工程做法。
- **PagedAttention/vLLM（2023-06-20 官方介绍）**：https://blog.vllm.ai/2023/06/20/vllm.html 。是 KV cache 的物理内存管理，不能与“选择哪些观测文字进入输入”混为一谈；它同时说明借鉴虚拟内存本身并不新。

## 5. 第一性原理：重定义问题，而非寻找更漂亮名称

有限上下文不能容纳全部数据；不存在对任意未知诊断问题都无损的任意压缩承诺。可控制的是：

1. 当前问题需要区分的观测差异是否在表示中存在；
2. 无法区分时是否能定位到造成混淆的那部分；
3. 细化结果是否真的进入最终输入，而非只停留在工具响应；
4. 缺少资料与预算不足是否被如实记录。

“稀有”“错误级别高”“非零”不等于诊断重要。“代表了某组”也不等于组内所有事实都与代表相同。静态全局重要性排序很难解决所有后续问题。

## 6. 候选 A：断言差异驱动的观测分区细化

工作名称：**一种基于断言反例定位的运行观测分区细化与诊断输入构建方法**。

状态：拟设计，现有模式分组、事实记录、归档入口可复用；动态断言检查、分区分裂和防再合并未确认已实现。

### 具体问题

按消息模板归并时，响应码、容器运行阶段、时间变化等差别可能被弱化。固定追加更多同类记录既消耗预算，也可能仍重复相同代表，不能修复造成误解的分组方式。

### 说明性例子（不是实测）

同一 Pod UID、同一查询窗口、同一 `/ready` 路径有大量 503 和少量 200。摘要只展示 503。模型提出“该窗口内已采集的 `/ready` 请求均返回 503”。

程序在同范围归档里找到一条 200：它是上述全称断言的反例，不是证明 Pod 健康，更不是证明根因错误。不能拿 `/work` 的 200 去反驳仅针对 `/ready` 的断言。

### 操作骨架

1. 固定观测域：对象实例、窗口、来源及已归档集合版本；建立粗分区与代表映射。
2. 将待检查内容限制为注册操作符的结构化断言，如等值、全称、存在、时间先后；字段缺失或自然语言无法无歧义转换时返回未知。
3. 在相同观测域中寻找使断言不成立的最小见证记录；未找到反例但来源不完整时不确认全称命题。
4. 找出同一粗分区中使断言真假发生差异的属性；只按该属性分裂相关分区，而不是扩大所有类别的记录数。
5. 下一次输入必须保留能表达该区别的子分区代表及其对象、时间、来源；对该版本和断言保留分裂约束，避免下一轮模板归并把区别再次抹掉。
6. 若代表及必要字段仍无法装入预算，返回未满足细化，而非继续声称该断言已核实；有限轮次/来源耗尽时终止。

拟比较的核心关系：**检查见证 → 定位信息损失的分区 → 改变分区 → 约束后续输入**。

### 为什么尚不能宣布创新

CEGAR 已有反例驱动细化；P3 已有字段子分组；主动检索与模型反馈重排也可能公开相近组合。必须对“使用有限真实观测上的断言差异决定分裂属性，且分裂约束跨后续压缩生效”进一步查新。

### 可验证作用与不保证事项

可检查：反例是否同域；分裂是否只影响相关组；产生区别的字段是否进入下一轮；相同误合并是否再次发生；增加多少 token。

不保证：自由自然语言根因正确、原始观测覆盖整个真实系统、未知故障被完全证明。

## 7. 候选 B：以最终输入包含回执控制增量补入

工作名称：**一种基于诊断输入包含状态的观测增量补入与预算准入方法**。

状态：拟设计；事实 ID、选择清单、归档读取和预算控制已有基础，事务式补入/最终包含确认未确认实现。

### 具体问题

按归档引用成功读回某条 Span，不代表经过工具摘要、工作流预算和交接投影后它还在下一次模型输入中。以工具成功或“曾传输过”作为完成依据，会出现读取完成但目标持续不可见。

### 操作骨架

1. 记录三种状态：源记录存在、工具已返回、当前输入包含。它们互不替代。
2. 补充需求绑定当前视图版本、目标对象、记录/类别以及需要的表示粒度。
3. 确定目标最小必要字段及成本，先为补入预留空间；从允许替换的重复代表中腾出容量，而非事后再走无约束截断。
4. 构建最终模型请求前核对目标 ID、必要字段及源版本是否实际存在于序列化输入。
5. 核对通过才把该补充需求记为已满足；否则保留待满足或显式失败。下一轮移出目标记录时，相应更新“当前包含”状态，不把历史传输记录当作永久可见。

回执是程序对实际构建输入的确认，不是模型阅读、理解或注意到该事实的证明。

### 与 JPIP、MemGPT 的比较

JPIP 已有缓存模型及增量交付，MemGPT 已有外存/上下文换入。仅增加 receipt、版本或缓存状态很可能属于常规组合。需要进一步证明：多级有损再压缩导致的状态错误，是否要求特定确认边界、原子字段集合及预算替换关系，而不是普通读取确认。

建议：工程上有用；专利上保守列为第二候选，不因其容易实现就认定更有创造性。

## 8. 暂不建议独立立项的方向

- “Flow/Span 轮流选一个”：与公平队列、分层抽样太接近。
- “少见记录优先”：P2 已有相关有限容量与低计数处理；少见也不等于有意义。
- “缓存已读 ID，下一次不重复”：JPIP/MemGPT 等背景很强，而且当前输入可能已移出旧记录。
- “更换分类器或加 BERT”：如果未改变实际处理关系，仅换算法名称不足以说明贡献。
- “把云平台/边缘云写入标题”：对象生命周期、观测字段或运行约束若未参与方法，应用标签不能替代技术差异。

## 10. 最后判断

本轮没有证据支持“现有方法已经足够新”，也没有证据支持“这个小问题完全没有空间”。已取得的材料足以否定过宽的主张，并将后续研究集中到两个可解释、可实施、可被近邻方案反驳的候选。

优先候选 A，不是因为它已被证明新颖，而是它把问题从“如何挑更多内容”变成了“如何用检查反馈修正造成信息损失的分组方式”。这比单纯新增摘要和回读接口更值得下一轮针对性查新。
