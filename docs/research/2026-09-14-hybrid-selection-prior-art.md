# 模型选择与程序取数：工程可用性及专利近邻复核

日期：2026-09-14。仅研究记录，未修改 Agent、MCP、测试或部署，未调用业务模型。

## 1. 本轮决定

“纯规则可能不够灵活，因此由小模型选择展开内容、程序按 ID 从源记录取数”是可以实施的工程组合，但本轮新证据不足以支持把它作为专利贡献。将其降为基础实施方式，不以增加一个 Agent 或减少模型参数量补足创新性。

本轮没有找到可以有把握推荐的新颖完整方法。此前的“字段回读偏差通过编码来源映射控制局部展开”仍只是待论证候选，参见 [候选及近邻对照](2026-09-14-decoder-feedback-representation-candidate.md)。不能用本轮发现的普通检索/过滤近邻直接判定该更具体候选全部相同，也不能因其尚有差别就认定具备创造性。

## 2. 新核读的非专利公开技术

### 2.1 Code execution with MCP

来源：[Anthropic 官方文章](https://www.anthropic.com/engineering/code-execution-with-mcp)，页面标注发布于 2025-11-04。本轮读取正文，含示例代码与限制说明。

已经公开的处理链：

1. 工具接口通过文件/API 呈现，模型按需查找和读取定义。
2. 模型生成代码调用工具，完整中间结果留在执行环境。
3. 代码执行过滤、聚合、多源连接或字段提取。
4. 只有显式输出的结果进入模型上下文；中间状态还可持久化到文件。

原文给出 10,000 行表格的例子：程序过滤 `Status == pending`，输出匹配数量和前五行，而非让模型读全部数据。其机制与“模型决定筛选条件，程序处理原始结果，有限输出进入模型”直接相邻。文中也明确要求安全执行环境、资源限制和监控，并提示新增运维开销。

不采用该文章报告的 token 节省数值作为本项目的效果证据。

### 2.2 Advanced tool use

来源：[Anthropic 官方文章](https://www.anthropic.com/engineering/advanced-tool-use)，页面标注发布于 2025-11-24。本轮核读 Tool Search Tool 与 Programmatic Tool Calling 部分、调用示例和适用限制；不声称逐项验证产品当前状态或全文所有性能数字。

- 工具搜索返回匹配工具的引用，再把相应定义载入上下文；支持延迟加载。
- Programmatic Tool Calling 由模型编写编排代码，中间工具返回交给执行环境，模型只接收最终输出。
- 差旅例子将员工、费用明细、岗位预算在程序侧求和及比较，仅返回超标者。
- 文章直接以大日志文件错误统计说明中间结果占据上下文的问题，不只是工具定义数量问题。

不能据此认定用户同事的完整申请缺乏新颖性：尚未取得其权利要求、优先权日和完整技术细节。本轮只排除把“动态暴露”或“模型选择＋程序过滤”抽象链单独视为新的论证。

## 3. 新核读的专利：US12008332B2

名称：*Systems for controllable summarization of content*；Anzer, Inc.；FPO 记载申请号 18/452496，申请日 2023-08-18，授权公告日 2024-06-11。

来源：[FPO 文本](https://www.freepatentsonline.com/12008332.html)。本轮读取其权利要求 1–20，并定向读取说明书的语义缩放、Progressive Disclosure、Natural Language Interactions、提示优化反馈段落。没有核对官方扫描件、同族、审查过程或逐项优先权支持，不称为完整法律意见。

### 3.1 其公开的连接关系

- 权利要求 1/11/16：确定内容及抽象层级，构造包含内容引用和抽象层级的提示，由 LLM 产生省略或简化子内容的表示，再据此控制输出。
- 权利要求 2/3：抽象层级可以与原内容长度/大小的比例相关。
- 权利要求 7/14/19：将表示用于后续提示，结合上下文生成对话响应。
- 说明书 Progressive Disclosure：默认隐藏详情，用户交互后按需展开。
- Natural Language Interactions：通过自然语言追问作澄清、定义和上下文扩展。
- 提示优化部分：记录内容、提示、摘要和用户反馈，更新提示工程模型；并描述辅助任务预测合适长度/抽象层级。

### 3.2 不能夸大的地方

该文献并不因此明确公开“严格按源记录 ID 取回事实、不允许模型改写事实”的全部实现。其部分保留信息机制是通过提示要求 LLM 不删重要内容，不能当作程序已保证事实一致。用户触发展开也不能直接等同于自主模型选择组 ID。

不过，“模型参与决定表示详细程度—生成短表示—按需扩展—交给后续对话处理”的上位思路已有相近公开，不能作为新颖性依据。

## 4. 第一性原理下的职责与边界

固定源集合 D，有限输入 S，诊断问题 Q。必须分别回答三个问题：

| 问题 | 可取得的判断依据 | 能保证的范围 |
|---|---|---|
| 源值是否复制正确 | 源记录、ID、字段路径、版本 | 程序可核对所取值及范围 |
| 所选内容是否适合问题 Q | 问题、目录、源端可计算统计；模型或既定策略 | 可以提出选择，不能保证关键线索全部覆盖 |
| 消费模型是否读懂 S | 对已知源字段的实际回读结果 | 仅证明所测调用/字段，不证明后续根因 |

增加小模型主要改变第二项，不自动解决第三项；另一个小模型正确回读，也不能认证消费模型读对。

### 一个必须暴露的选择盲区

构造两个同样 1,000 行的日志集合。A 全为 503；B 有 990 条 503 和 10 条 200。如果目录只显示经过状态数字泛化后的共同模板、总数与相同首尾示例，目录可能完全相同。

在问题和输入目录相同的情况下，选择模型没有依据区分 A 与 B；随机采样只会给相同的输出分布，不能解决信息不可区分。这不是实际模型测试结论，而是输入信息相同的边界。

程序加入源字段 `status` 的频数分布可以区分该例。但这只是可实施的工程修复，不是新颖性主张；如果差异在未解析的自由文本字段，固定状态分布也不够。不能写成“增加小模型后自动识别被目录完全隐藏的异常”。

## 5. 一个可实施但不作为新点主张的组合基线

1. 程序固定源快照，按明确字段生成目录，标记解析失败及未展示内容。
2. 选择模型接收诊断问题与目录，只输出组 ID、字段及范围，不直接输出新的事实值。
3. 程序校验对象、快照版本、字段和预算，从源记录生成展开结果。
4. 诊断 Agent 接收展开结果，必要时追加请求；限制轮数、耗时及重复读取。
5. 目录无法区分或选择失败时，允许显式请求其他源分区；容量不足则披露未覆盖，不把未读取当作不存在。

小模型可选：先由现有诊断模型完成选择也符合此基线。是否拆给小模型取决于调用成本、选择质量和延迟，不通过增加角色预设收益。程序接受选择请求只表示它合法可执行，不表示它诊断上充分。

## 6. 对后续专利研究的实际约束

- 不再研究“给普通选择流程加一个小模型”作为独立贡献。
- 若继续表示局部展开候选，必须比较编码来源映射怎样约束变换，与已知字段反馈提示优化及静态展开模板的差别；不能用本轮的筛选基线替代最接近的比较对象。
- 若提出其他候选，须明确它处理的是源端缺失、输入未展示还是消费误读。三者不能被统一写作“信息丢失”后用一个模型处理。
- 本轮材料支持一个负向筛选决定和混合方案的完整工程边界，不支持宣布找到了具备创造性的最终专利方案。
